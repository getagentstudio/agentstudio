Exact-state comparisons below remain diagnostic loss-characterization arms; their equality failures do not by themselves block the initial integration. ## E1 — Terminal restoration, continuation and native rendering

**Hypothesis:** a restoration checkpoint plus its following live stream produces the required terminal state and remains correct when the next bytes arrive.

The earlier comparison names vendored ZMX `8bab1f0` Init and research candidate `2d23c0d` Init/Capture. The executed backend comparison instead used `0a18bee`, whose protocol header differs from the earlier candidate; its [results and pins](../designs/04-terminal-runtime/research/backend-observations-2026-10-20.md) govern any reuse of that observation. Compare against uninterrupted parsing of the same bounded synthetic corpus, keeping ZMX's VT pin `8af6897c` and the app renderer pin `2fb0c9ca` distinct. A full-transcript reference belongs only to the bounded experiment fixture; it does not introduce a production transcript store. The negative reconstruction result now justifies investigating a complete-checkpoint realization, without selecting a production format or another Host VT by assumption.

Capture arms must use the **same connection** that carries following live Output: B-leader sends Init then Capture on that connection; B-observer sends no Init and no input, then Capture on its live connection. The shipped capture CLI's separate connection followed by a new attach has no shared cut. Observe automatic device-attribute replies in the no-Init arm. No-Init is not itself an input restriction: qualifying input can promote that client to leader even before Init; this can also leave ZMX auto-answering queries because its terminal-client flag is still unset. Score that interaction explicitly.

Use short corpora with known expected state and exhaustive cut positions: partial UTF-8/CSI/OSC/DCS, wide/combining text, title/CWD/prompt marks, scrollback, alternate screen, wrapping/cursor, styles and input modes. Add a continuous synthetic TUI producer, a resize and two viewports. Observe actual chunk boundaries, including the per-chunk OSC133 rewrite. Distinguish raw backend state from deliberately transformed client bytes; applying the same transform to both paths must not hide a transform defect.

**Oracle:** compare cells/styles, cursor/wrap, screens, required modes and metadata at a declared cut, then feed a canary suffix that exposes parser residue. Score each element separately. Declare intentional restoration normalization, such as the existing exclusion of synchronized-output mode, rather than requiring equality to every transient bit. Negative controls must deliberately change an observable required element; an arbitrary one-byte shift is not guaranteed to do that.

Prove the native leg through the actual Ghostty surface and a relay behind its PTY. Controlled terminal output—not `ghostty_surface_text` input injection—must emit terminal queries, with responses captured at the correct return boundary. Text reads prove parser/text state; sampled pixels prove the sampled images. Neither alone supplies a frame-presentation timestamp.

**Decision:** a passing profile makes a relay/Capture design eligible for E2/E3 evaluation. It does not alone select that design. Missing state, overlapping restoration or parser divergence identifies the needed backend/protocol change. Capture's distinct ordered frame is a possible per-client barrier, not an assumed complete parser checkpoint. Do not invent an accept between PTY parse and broadcast inside the current single-threaded section; exercise actual accept→broadcast→Init orderings.

Record divergence by element/cut/pin, restoration bytes, CPU/allocation cost and time to correct observable state. Unobservable elements are inconclusive. A baseline pass does not establish every TUI or an older running daemon's capabilities. The broader [E1 restoration procedure](../designs/04-terminal-runtime/experiments/terminal-restoration.md) separates owned-VT, backend-protocol, real-PTY, native and full-route proof. Bounded backend and snapshot-component arms now have results; native and full-route qualification remain incomplete.

## E2 — Host autonomy, authority and effect receipts

**Hypothesis:** view/connection loss does not end the session or authorized work, while delivery uncertainty never becomes an invented effect result.

The [source desk classification](../research/evidence/2026-10-15-daemon-extraction-survey/e2-effect-boundaries.md) covers 57 app RPC names, 44 Git operations and 16 Bridge calls with 22 nested annotation operations. It records effect boundary, correlation identity, post-state observability, duplicate behavior and cancellation/settlement custody as separate axes. This is source coverage, not executed proof; the 154 AppCommand identities retain their separate inventory. A mutation may support both reconciliation and deduplication; there is no universal request-ID solution. Generic Bridge success can wrap a failed/partial typed payload, and some stale/error results follow an already-applied effect.

Future runtime arms cover:

- Create a session before any renderer, produce title/CWD/activity/exit facts, detach and close the app. Compare named semantic facts against a declared reference, preserving their real ordered-versus-latest-state policy. Include long CWDs: current ZMX Info truncates to256bytes and carries no title/activity field.
- Exercise scoped agent admission and revocation independently of native pane membership. Targeting sessionB with sessionA authority is a meaningful refusal case. A transferable bearer used within its valid scope is not automatically a failed process-attestation test. App-closed transport unavailability is also different from authorization refusal.
- Inject loss before admission, after admission/before effect, after effect/before Host reply, and between Gateway reply and client receipt. Count the effect independently through real fixture state; distinguish explicit rejection, completed/partial/unknown effect and reconciliation. Retry only operations with a declared duplicate contract. Never replay uncertain terminal input automatically.
- If restart preservation is selected, crash/restart the Host around admitted work and verify the required re-adoption/recovery outcomes. This arm measures a candidate restart contract; client-absence continuity alone does not authorize automatic workload restart or unlimited durable history.

**Oracle:** correlated effect evidence plus the caller's typed outcome, current authority revision and exact execution incarnation. Calibrate the effect counter with a deliberately duplicated observable fixture effect; disabling dedup does not necessarily duplicate an intrinsically idempotent operation. No false success from a sent Kill, socket disappearance or failed process inspection.

**Decision:** identify which operation classes need retained receipts/keys, post-state queries or an explicit irrecoverable-unknown outcome. Determine what evidence a registry/fact owner must retain for the selected recovery promise. Authorized in-session agent/hook/context input uses its Host locally. Exercise that selected path with every Gateway (macOS or iOS) unavailable; this is not a frontend bypass or an outbox arm. IP3 now sends worktree machine CLI to its attached local Host daemon and selects local activation when absent. UX/frontend CLI remains through Gateway. The Host-local proof arm does not bypass that selected frontend route.

Include real Swift process ↔ Unix socket ↔ Rust Gateway interoperability for every selected schema/variant and rejection surface in both directions; separately exercise Rust Gateway↔Host network compatibility. Use one schema authority, with explicit null/absent, integer, enum, timestamp and path-encoding cases as the selected contract allows. Then test semantic validation, maximum/fragmented frames, cancellation and incompatible-version refusal before mutation. Verify any generated code against the exact safety/lint policy. Broad codec-speed comparisons can wait; basic protocol/framework feasibility cannot be assumed.

The unexecuted [E2 autonomy and effect procedure](../designs/07-agents-context/experiments/host-autonomy.md) distinguishes renderer absence from Swift-process/Gateway absence, source/reduction/effect/caller observations and finite A0–A14 cases. Metadata comparison declares hostname/path interpretation and current title-size boundaries; matching ZMX Info or a surviving shell does not establish complete renderer-free facts. Host-local in-session ingress is selected; exact authority and restart promises are not supplied by the fixture.

## E3 — Coordination, fanout, slow viewers and memory

**Hypothesis:** each traffic class preserves its promised semantics under lag while resource admission and cleanup remain bounded.

For coordination, replay the same admitted semantic input trace through scoped owner subscriptions and a shared typed fact-hub candidate. Require equivalent exact-transition/latest-state/request-result outcomes before comparing cost. Observe stale-generation rejection, gap/resnapshot behavior, equality suppression, Swift publication volume and queue age. A faster lossy implementation does not win an ordered-fact comparison.

The [coordination and Swift publication procedure](../designs/10-swift-client/experiments/coordination.md) defines the source baseline, comparable arms, traffic-specific oracles and finite C0–C14 cases. It separates producer admission, subscriber delivery, actual owner effects and native publication; source labels and generic acknowledgements are not assumed to prove continuity or completion. Noisy/quiet producers, source cardinality, causal dependencies across producers and replay/live handoff are explicit discriminators. This procedure is unexecuted and selects no bus topology.

Also use two distinct Hosts with identical local paths/session labels through one Gateway. Disconnect or stall one Host and independently verify routing, availability and progress for the other. Exercise more than one Gateway sharing a Host separately; counts of in-process subscribers are insufficient. Any cross-Host listing needs a declared partial-result contract before scoring completeness.

For terminals, compare multiple ZMX attachments, one Host attachment with per-viewer fanout, and applicable Gateway fanout. Use160×48 and40×20 views, a reader that stops draining, bounded output bursts and a controlled controller transfer. The current N-attachment design is a baseline, not a preordained failing negative control. Calibrate the meter with known bounded allocations/queues instead.

Score two different backend outcomes: growing retained output and a silent VT gap when appending Output fails for a client. The current loop can skip that chunk without a marker. Use a controlled, bounded failure injection and E1 canaries that expose the selected lost-state case; do not force OOM on a shared machine or call a semantically invisible dropped byte a failed oracle.

**Oracle:** semantic outcomes, actual PTY size/SIGWINCH observations, an active viewer's progress, and E1-correct state after a lagged viewer resumes. Declare the controller policy being evaluated; an experiment cannot choose it. Exercise reattach/resnapshot overlap, controller loss and a queue boundary. Keep reading/draining custody separate from subscriber lifetime.

Declare child-visible focus separately from attachment fanout. With DECSET1004 enabled, ZMX's [terminal-client presence transitions](../../../../vendor/zmx/src/loop.zig:248) can inject focus-out/in; a surviving Host Init attachment suppresses that particular transition even when no frontend is viewing. A leader's [input path](../../../../vendor/zmx/src/loop.zig:894) can still forward focus bytes, so permanent focus does not follow from attachment presence alone. Record all actual focus inputs and the producer's changed output. Human/native/multiple-client focus meaning remains a controller contract to settle, not a hidden consequence of selecting one shared Host attachment.

Report logical queued bytes/items, actual allocations/process footprint and relevant kernel/transport observations separately. Flow-control credit is not allocated memory; shared backing buffers must not be double-counted. Bounded stress samples support measured behavior, while an inspected admission/allocation contract supports the general bound. A blocked producer that cannot reach the next volume checkpoint is an observed outcome, not a polling wait.

**Decision:** select eligible recovery/fanout candidates and expose their cost/budget location. Terminal byte dropping is acceptable only with a proven recovery contract, not arbitrary VT loss. Snapshot CPU/retained bytes and tasks blocked upstream belong in the accounting. Final latency and resource budgets remain explicit tolerances.

## E4 — Safe Linux capability and parity

**Hypothesis:** the Linux realization can preserve the published Mac contract, including failure and partial-effect meaning, through safe Rust interfaces.

Begin with a narrow clone/containment/metadata probe on pinned isolated Linux profiles: one that supports the required clone capability, one that refuses, and a cross-device case. `FICLONE` is a cloning primitive. `copy_file_range` can accelerate copying but does not guarantee cloning; it is not a substitute or silent fallback. Filesystem names alone are not universal capability verdicts.

Expand only after that discriminator to the F01–F13 cases: descriptor containment and ancestor swaps; changed sources; file/link/hardlink/special-node handling; admitted metadata/ACL/name behavior; nested Git administration/index adoption; LFS materialization; ref locks/CAS; cancellation, partial effects and owned cleanup. Add process/peer/boot/file identity and filesystem-observation continuity/overflow. Compare equivalent semantic contracts, not identical OS APIs or stat-cache tricks.

**Oracle:** real filesystem/Git/process outcomes against the existing Mac contract matrix, with independent source/destination identity checks. A refused capability must be truthful and occur at its declared effect boundary. Cleanup may complete or return accurate typed residue/partial effects; “zero residue under every failure” would contradict existing receipts. Testing cannot authorize removing required Linux features—report parity gaps and bring policy tradeoffs back.

Linux watcher probes need ground-truth mutations, rename/new-directory races and overflow/quota handling. Inotify is nonrecursive; fanotify filesystem marks have privilege constraints. Watcher parity was already a known survey gap; this makes its experiment concrete. Do not alter host-wide kernel settings or mount user data to manufacture a test environment.

The owner has offered Fly for Linux testing and explicitly requested Fly CLI login. A prior successful login is not current execution readiness: the actual authenticated control path must pass at experiment preflight, followed by the selected guest/tooling checks. A fixture must record the actual kernel, filesystem, volume/mount and clone/metadata/privilege capabilities before interpreting a result. One VM profile cannot establish every required Linux capability. The 21 October bounded Fly task/copy probe and existing-Sprite watch fault probe have now run; the [current results](../explainer/progress.html) distinguish overlay-root and ext4 `/tmp` observations. The task-only Fly VM was independently confirmed removed; full Linux fork/Host parity remains open.

The [first Linux feasibility probe](../designs/06-worktree-fork/experiments/linux-feasibility.md) defines the broader experiment envelope, required environment receipt, filesystem qualification algorithm, synthetic corpus and C0–C10 oracles, revised against the source-checked Advisor challenge. Its first gates qualify the foreground control/transfer/build path. It is a leaf/API discriminator with no Fly volumes; full F01–F13 fork parity remains a later obligation. Do not infer complete C0–C10 or safe-Rust qualification from the narrower executed task/copy/watch arms; use their named observations and targets.

**Decision:** expose actual safe-wrapper/backend coverage, eligible platform profiles and remaining Linux work. A byte-correct clone does not prove metadata/tree/rollback parity. All first-party prototype code inherits the requested no-unsafe and lint rules; no exception is assumed.

## E5 — Full-route latency, contention and compression

**Hypothesis:** the required route meets the eventual interaction/resource tolerances under competing traffic, and attribution identifies the cost worth changing.

The intended terminal reference is today's local Ghostty→attach→ZMX path versus the required client→socket→Gateway→Host→ZMX path for Mac-local and Linux-remote work; comparable observations must exist before interpreting that difference. Current source does not establish that matched terminal observer. E2-confirmed equivalent control operations can be compared separately. Keep a fresh CLI process benchmark separate from a persistent-client socket exchange. Observe actual Tailscale/direct/relay path type when applicable; do not assume the user's current topology or infer a steady route from discovery packets.

The [existing latency-observation source review](../research/evidence/2026-10-15-daemon-extraction-survey/e5-latency-observation-evidence.md) identifies today's CLI metric as parent-before-fork through process exit, with 13 method families plus startup/help and separate unmeasured families. Its current budgets and result-shape checks do not establish new-route acceptance or independent effects. Loaded native claims also require the owning real-load profile; the small E3 correctness corpus is insufficient for that claim.

Use a controlled echo producer and a synthetic TUI while real bounded Git/review/file-content work and another terminal compete. Compare stream/connection layouts and compression off/on on identical payloads/results. Include retained review seed versus full recomputation only as a scoped sub-arm. MessagePack is encoding, not compression. Defer broad serializer bake-offs until stage attribution shows they matter.

**Oracle:** distinguish key→terminal parser state, key→observed pixels and key→actual presentation. Use the strongest real observation seam available and label the rest as unproved. `read_text` cannot establish display presentation. Keep end-to-end durations on the client clock; use correlated local monotonic stage durations for attribution. Validate probes with an injected controlled delay and an output-disabled calibration whose expected result is unambiguous.

Apple's [ScreenCaptureKit displayTime](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/displaytime) is a candidate WindowServer-frame observation, not yet a calibrated latency instrument. Verify timebase/units, clock alignment, frame association, availability and refresh quantization with a known on-screen event. Request any capture/input-automation grants only if the selected execution/observation path needs them; do not assume every native leg requires Accessibility.

Report p50/p95/p99/max with sample counts/variation, correct/missing/wrong echo separately, queue age, throughput, CPU, allocations and retained bytes. Include first-correct-state/reconnect time and compression wire-byte/CPU costs. A percentile is not a correctness deadline and does not hide failed observations. A glyph-present measurement needs a validated native/render timing seam; if unavailable, that claim is inconclusive.

**Decision:** price the mandated route without bypassing it. Compare eligible congestion/stream layouts and per-class compression using observed effect sizes and uncertainty. A product pass/fail requires owner tolerances; exploratory comparisons can still report costs before targets are fixed. No sub-millisecond or Rust-speed promise is assumed.

The [full-route cost procedure](../designs/11-operations-integration/experiments/route-performance.md) defines comparable arms, finite populations, calibration, contention/compression cases and separate result/effect/native observations. It includes source-qualified transport and native evidence. Current client-clock parser/presentation and current-versus-new terminal cost are ineligible under the identified observer gaps; new-route byte-echo variants do not substitute for them. It remains unexecuted and selects no transport, codec or owner budget.

## E6 — Phone socket and app lifecycle

**Hypothesis:** the required iOS Gateway can start under IP6, serve the UX client's typed local socket contract and reconcile valid state after actual mobile lifecycle changes, while Host execution stays independently alive. This is an unexecuted qualification proposal; S28 already selects the mobile role.

**Startup and safe-boundary gate.** Identify the actual iOS toolchain, target, application artifact, Rust runtime entry/lifecycle path and every first-party/generated/native boundary. Build under the declared first-party unsafe ban. A business socket does not itself select a Rust–Swift business FFI API, but starting Rust and delivering lifecycle transitions still need a concrete compliant path. Check the exact export attributes and macro provenance against the [Rust unsafe-code lint](https://doc.rust-lang.org/rustc/lints/listing/allowed-by-default.html#unsafe-code); do not turn a reported desktop compile result or a generated facade into iOS compliance proof. A failing candidate is refused under the current profile, not silently granted an exception or relabelled as a dependency.

**Local interaction gate.** Run the real UX producer/consumer and Rust Gateway over the selected same-device socket boundary. Observe declared frame/schema variants, rejection, interruption, runtime shutdown and actual readiness. Distinguish this local leg from the Gateway↔Host network leg. For a named Unix socket, derive byte/path limits and custody from the actual SDK and installed container path; a template length is not a universal installation limit. A socketpair/alternative local shape is not selected without its own startup/ownership contract.

**Physical lifecycle gate.** Distinguish background transition, confirmed suspension with any surviving resources, connection loss, process termination and resume/relaunch. Observe which happened rather than inferring suspension from a callback or elapsed sleep. Check listener and connection state, current handshake/target authority, appropriate current reads or selected-copy refill, ordered terminal restoration and UX currentness. Do not assume AF_UNIX listener reclamation from archived TCP/UDP guidance, or universally require a full snapshot when continuity is established. Startup/resume must not duplicate execution or automatically resend uncertain keyboard/operation effects.

**Oracle and countercases.** A separately observed Host workload/fact source continues while the phone's UX/Gateway is absent. On restored availability, the actual phone path reaches the same declared Host resources and current qualified state under R16/R17; stale generation, invalid authority, wrong target, listener failure and interrupted restore remain truthful. A simulator build/socket interaction does not establish physical-device suspension, provisioning or supported installation. Use the actual platform facts/readiness/lifecycle observations; do not add polling or wall-clock correctness budgets.

**Decision informed:** safe startup/lifecycle adapter, local socket custody and supported resume/refill profile. Passes close only their actual target/boundary. No product experiment is run by this document. It grants no unsafe exception, independent always-running iOS daemon, app extension, push sender, new service, codec or input-replay policy.
