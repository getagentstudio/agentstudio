# The 154 commands: current execution and proposed integration

**Trace the actual owner behind a command before moving it.** This map follows every current `AppCommand` through typed `command.execute` to its immediate effect, forwarding owner or refusal. Proposed integration is the Lead's structural interpretation of Host/Gateway/native roles. It is not a selected replacement API or complete Program Design.

Source baseline: AgentStudio `624300332f5e50f7bb8cbb9fc786d5e5b4a3d462`. All 154 identities reconcile with the current enum and typed argument/result projections. [Source rows](../../research/evidence/2026-10-17-daemon-capability-placement/command-execution-source-map.json) retain branch, native dependencies, declared results, pointers, evidence reuse and remaining gaps per identity; [research notes](../../research/evidence/2026-10-17-daemon-capability-placement/command-execution-source-map-notes.md) explain the source walk. The deciding switches and immediate owners were read; deeper effects are not uniformly audited or executed. No runtime success or repair is claimed.

The [identity and dispatch overview](command-operation-map.md) owns the 24 all-channel / 130 debug-testing and 143 headless / 11 presentation classification. Exposure and mode are independent; even an all-channel presentation identity needs the debug-testing dispatch admission. Current typed argument tags below come from the existing catalog, not a newly selected schema.

## What the current result labels hide

- Nineteen identities explicitly return feature-unavailable: twelve dormant Inbox, three retired Panes-sort and four typed worktree-creation commands. Two pinned-navigation identities separately return state-unavailable; interactive paths are not that typed route.
- Five typed drawer-entry/directional-focus paths can pass validation and reach a coordinator branch that logs only. The executor reports applied after a nonthrowing coordinator return; it does not independently read the requested effect back.
- Seven terminal-navigation commands map runtime success and queued to applied. Six relative-focus commands return applied after a void trigger call. Neither observation proves completed rendering or focus.
- Typed openWorktreeInPane derives terminal insertion from target-pane CWD and does not read the supplied worktree ID on that route. Target names alone cannot establish the machine/resource actually used.
- Presentation, scheduled management work, external effect initiation, Bridge acceptance, source acquisition, SQL commit and rendered output retain separate boundaries.

These are current-source design risks, not reproduced runtime incidents or authorization to repair product code. The target contract must choose a truthful effect/result boundary, then its implementation and Verification Design must show that boundary on the actual target.
