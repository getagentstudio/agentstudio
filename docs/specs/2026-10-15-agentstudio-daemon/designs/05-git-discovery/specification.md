## K1 — Git operations other than fork

**Consumer / entities / basis:** worktree, review and CLI users; E7/E8/E22; U4–U6/U9/U11, R2/R4. Current behavior is the pinned [Git operation desk](../../research/evidence/2026-10-15-daemon-extraction-survey/e2-git-operation-evidence.md) and [non-fork contract evidence](../../research/evidence/2026-10-15-daemon-extraction-survey/capability-git-contract-evidence.md). These enumerate all forty-two non-fork SDK operations in the forty-four-operation survey; they are not forty-two selected RPC methods.

## K3 — Discovery, inventory and refresh

**Consumer / entities / basis:** repository sidebar and operator; E7/E8/E22; U4/U6/U11/U13. Intake, scanning, canonical membership and a displayed projection are different observable facts. Exact-candidate discovery does not search ancestors; invalid/unreadable evidence is not successful empty inventory.

The current topology path rechecks source/sequence/root/baseline before applying membership. A scan result alone is not an authorized mutation. Persistence failure after graph/effect application cannot be reported as an atomic untouched operation. Inventory root/config/ignore and currentness belong in the selected contract; exact cross-client membership and restart meaning remain G3/G9.

Git, remote and Forge attention/demand currently differ. A complete empty Forge result for no demanded branches says nothing about all repository PRs. Failed, rate-limited, truncated, no-demand and complete-empty observations must remain distinguishable for a selected feature. The Host supplies repository facts independently of a Swift view; client attention can inform refresh coverage but does not become another repository owner. Full-host frequency, cross-client demand and retained no-client coverage remain G9 and are not established by today’s focused-window policy.

Filesystem change observation is a separate cross-platform boundary within this family. The current [Darwin registration](../../../../../Sources/AgentStudio/Core/RuntimeEventSystem/Filesystem/DarwinFSEventStreamClient.swift:28) carries registration generation, root, status-observation identity/scopes and continuity witnesses. Its [ingress overflow](../../../../../Sources/AgentStudio/Core/RuntimeEventSystem/Filesystem/DarwinFSEventIngressBuffer.swift:66) retains recovery and marks continuity uncertain rather than treating dropped batches as complete. A selected observation contract must name watched coverage, source lifetime/position, canonical path/alias provenance, registration failure, overflow/lost coverage and what a later refresh can reestablish. Silent loss cannot count as fresh complete coverage. G7/G9 retain the Linux counterpart's supported limits/continuity profile; this does not select a Linux watcher API or a new public watch method.

**Proof:** real candidate filesystem and membership transitions with stale/raced observations; ground-truth file changes including rename, new directory, alias and admitted overflow/loss cases on both platforms; actual local/remote/Forge source boundary for whichever features are selected. Cached values or an empty array cannot prove full fresh coverage. K11 covers publication; G7/G9 retain exact observation, inventory and demand profiles.
