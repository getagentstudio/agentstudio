## CLI entry syntax is another layer

The 293 declarations below do not count CLI parser verbs, argument branches or installer/hook child-process entrypoints as app command identities. The [18-family source map](capability-placement-map.md) separately carries standalone worktree CLI, provider-package installation, provider hooks and pane verbs. Their routing, bootstrap and producer-local state must be traced in each selected slice. No claim of complete CLI syntax/argument coverage is made by the five-layer count.

## How one command reaches its work

Preserve current command identity and display/shortcut metadata. Classify its parts as addressed Host work, selected logical workspace mutation, actual native interaction or Gateway read/interest. Route each part to that owner with its declared authority and result. The app command catalog is not replaced by the Git SDK list or one untyped global execute message. Native-only actions can remain local; external frontend Host work follows Gateway.

For example, a terminal-creation action can request execution at one Host, place its logical view at the declared workspace authority, then mount a native surface. Those steps retain separate failure results. Similarly, an unavailable typed worktree wrapper does not make the interactive worktree feature unavailable.

## Limits and additions

Exact set reconciliation detects a recorded identity dropped by this index; it does not detect a feature never inventoried, a changed argument branch or an effect hidden behind a current facade. New discoveries join the owning feature branch and operation map before migration. No source-form count checks a feature off. The [near-term slice](near-term-migration.md) names its required contract closures.
