# E5 full-route cost and contention experiment

Measure the cost of **client → socket → Gateway → Host** without confusing a queued write, a Host effect and a displayed terminal echo. Compare stream layout, scheduling and compression only after each measured path produces the correct outcome. This procedure is unexecuted; it selects no transport, codec, service allocation or product latency/resource target.

The [requirements](../../../user-requirements.md) own product meaning. Host parity includes macOS and Linux; the Gateway role runs on macOS and iOS under S28. Each UX client uses its device Gateway, with no required Mac relay for phone access. Host-local session inputs and machine worktree CLI retain their separately selected R9/R12/IP3 entries; they are not frontend bypasses. Mobile hosting, suspension and actual observations remain qualification work. The [primary experiment map](../../../experiments/primary-experiments.md) owns E1 terminal correctness, E2 effects/authority, E3 coordination and E4 Linux qualification. Those dependencies are claim-specific: an early control baseline does not prove terminal restoration or native rendering.

## Questions and observations

| Question | Observation that can answer it | Claim it cannot establish |
| --- | --- | --- |
| What does a fresh CLI call cost? | Parent monotonic time before fork through process exit, retaining process/result failures. | Persistent socket exchange, server-only work or displayed echo. |
| What does a warm client exchange cost? | Client monotonic duration from offered call and separately actual submission to a validated correlated result on a reused authenticated connection. | Operation effect beyond its contract, cold handshake or indefinite connection lifetime. |
| Where does a delay occur? | Correlated **local** monotonic spans and queue age at the client, Gateway, Host and relevant owner. | Cross-machine one-way delay from subtraction of unrelated clock readings. |
| Does a small control/input operation progress during bulk work? | Its correct result/effect and latency, plus bulk progress, queue age, retained memory and admission outcomes. | Fairness from a priority setting alone, or unlimited boundedness from a finite run. |
| What does terminal interaction cost? | Separately correlated input admission, controlled producer receipt, matching terminal state and, where qualified, pixels or presentation. | PTY consumption from socket success, or presentation from a text read. |
| Does compression help? | Identical decoded results, end-to-end costs, codec CPU/allocation, retained state and clearly scoped byte counts. | Speed from compression ratio alone, or physical-link savings from a protocol counter. |

Source baseline: AgentStudio `624300332f5e50f7bb8cbb9fc786d5e5b4a3d462`. The [existing observation review](../../../research/evidence/2026-10-15-daemon-extraction-survey/e5-latency-observation-evidence.md) distinguishes today's CLI process metric, scoped sequential authenticated exchange, asymmetric frame bounds and real-load proof requirements. Transport/native evidence and their unresolved observation seams must accompany an actual run; no benchmark numbers accompany this document.

The [transport evidence](../../../research/evidence/2026-10-15-daemon-extraction-survey/e5-transport-observation-evidence.md) pins Router-resolved Quinn 0.11.11 / quinn-proto 0.11.15, tokio-util 0.7.18 and async-compression 0.4.50. Pinned Quinn flush is a no-op, finish does not await delivery, stream acknowledgement excludes peer processing, and local send priority does not prioritize the opposite direction. Its connection UDP TX counters advance before the protocol returns a transmit to the socket layer. Router's compression precedent decodes HTTP inspection copies; it is not existing outbound terminal compression, and its decoder CPU runs during polling. These are source/API facts, not measured cost or a stack selection.

The [native evidence](../../../research/evidence/2026-10-15-daemon-extraction-survey/e5-native-observation-evidence.md) traces the pinned Ghostty input, PTY/parser, query-reply and IOSurface paths. Text reads inspect locked parser state; GPU completion can precede queued main-thread layer assignment and size-mismatch discard. Existing interaction probes do not correlate terminal keys with presented frames. Therefore parser progress, assigned contents, sampled pixels and actual presentation require different observation contracts. The exposed path is not a terminal CAMetalDrawable presentation receipt.

**Observation decision:** this procedure selects no parser-text sampling instrument or new production hook. With the currently identified public app surfaces, P4 client-clock parser and presentation latency are **ineligible/inconclusive**, rather than a measurement P0 can already qualify. The C text-read API is pull-only and contends on parser state; the current app IPC `terminal.snapshot` exposes metadata, not that text. A future explicitly admitted, finite sampling instrument would need a declared cadence/resolution, read brackets, stable canary visibility/correlation and P8 perturbation proof; it would report sampled/bracketed state, not an exact parser-transition timestamp. That is a separate observation-design gap, not permission to add it here.

P3 may instead measure a qualified **client terminal-byte echo**: a controlled producer's unique marker received through the full client socket/Gateway/Host byte path. It does not include native parsing or presentation. Producer-side terminal query/reply roundtrip is another separately timed observation on that producer's clock; it is not client key-to-parser time. No shared raw timebase between processes, languages or machines is assumed merely because both processes run on a Mac.

**Baseline decision:** P3 compares eligible **new-route arms only**. Today's Ghostty → attach → ZMX path has no matching client-byte observation established here, and P4 has no eligible native latency observer. Current-versus-new terminal cost is therefore ineligible until both have equivalent observations; this remains an open measurement obligation. No direct ZMX fixture client or vendor/probe change is selected as a substitute for the actual current route. A byte-echo result cannot be subtracted from today's CLI or native timing to price the terminal route's added cost.

## Freeze each run before measuring

Record the claim, candidate source/build/artifact identities, exact operation and payload corpus, response/effect oracle, client/Gateway/Host execution identities, connection and attachment lifetimes, wire/codec versions, frame/content limits, queue/admission policies and cancellation custody. A source HEAD plus an independently hashed binary does not alone prove their build lineage.

Record OS/architecture, runtime/thread configuration, CPU/power conditions, load throughout the sample window, host placement and observed path. Distinguish Mac-local Host, remote Linux Host, and any controlled network-condition fixture. Record actual direct/relay state if such a network is used; do not assume Tailscale, direct connectivity, a Fly filesystem, NIC offload or steady route type. Do not change shared host networking to create a test condition. New isolated environment/fault tooling remains an unqualified prerequisite until inspected and authorized for execution.

Use the existing dedicated debug/fixture identity and production authentication semantics for current baselines. The experiment does not disable authentication, extend the original deadline, reuse another pane's credentials or read private fixture files during this source-design work. Future fixture tokens and telemetry remain owned and redacted; no private payload belongs in exported metrics.

Every condition has a finite workload and a declared resource envelope. Initial comparison uses three paired repetitions per eligible arm, with 200 control exchanges and 200 terminal canaries **in separate profiles**, plus at most 64 MiB of offered bulk data per repetition. Report all failures and the limited tail resolution; these sizes are exploratory sample caps, not owner targets or evidence of all production populations. A runner's unchanged hang bound ends an uncompleted run as inconclusive; increasing it cannot turn incorrect or unobserved work into a pass.

Hold the externally admitted in-flight request limit equal across route comparisons: begin at 1. A separately declared 4-in-flight profile may follow only when both arms can realize it, with actual connection counts and client/owner admission recorded. The current exchange is sequential; comparing it with a pipelined candidate at a different concurrency is a concurrency/capability comparison, not isolated route cost. Pre-submission harness queue age belongs in offered-load accounting. Freeze exchange grouping/deadline scopes before the run; 200 observations need not mean one indefinitely reused scope. Never omit, reset or extend the current original deadline to avoid censoring.

Use two populations separately:

- **Closed-loop:** one measured request or native canary in flight, plus separately declared competing workload. This prices submitted interactions under that offered pattern.
- **Scheduled offered load:** a fixed finite input schedule independent of completion, with offered time, actual submission/admission time, pending/refused/cancelled work and response time recorded separately. A growing wait before submission must not disappear from the report. Stop offering at the declared cap and account for the still-pending work before retirement.

Do not pool these populations or claim the closed-loop workload represents an input stream that keeps arriving during a stall. Actual rates and event schedules are frozen in the run manifest after the observation path is qualified; no product input cadence is selected here.

| Comparison | Hold fixed | Change and price |
| --- | --- | --- |
| Current and new control route | E2-confirmed equivalent operation/result, fixture state and observation level; declared cold/warm conditions | Eligible current local control operation versus the full client/socket/Gateway/Host realization. Not every current method is automatically an equivalent Host operation. A synthetic transport probe is separate from a real domain operation. No direct frontend→Host candidate. |
| Current and new terminal route | Requires a matched observer and start/stop meaning in both arms | Currently ineligible under the baseline decision. P3 compares new-route variants at byte-echo level; P4 native latency remains unqualified. Do not replace this missing baseline with a differently scoped backend measurement. |
| Process and persistent exchange | Same operation, authentication policy, payload and result oracle | Fresh CLI lifetime versus scoped reused authenticated socket. Record connection/auth/handshake work separately; the current scoped exchange shares its original deadline. |
| Stream scheduling | Same full route, connection count, semantic payloads, resource admission and network profile | Baseline send scheduling versus one explicit priority arrangement. Observe both directions independently and bulk progress; do not infer reservation or preemption from the API. |
| Shared and separate transport connections | Same Gateway/Host roles, total offered workload and declared total resource envelope | One multiplexed connection versus explicitly separate connections, if both candidates are eligible. Count extra handshakes, congestion state, buffers, tasks and any aggregate share change; a second connection is not a free gain. |
| Bulk/control placement | Same operation results and exact bytes, authority and recovery semantics | Large framed application responses sharing the control lane versus a declared separately carried bulk payload. Independent terminal streams alone do not answer large-RPC-frame interference. Any unimplemented binding/cancellation contract is an E2 gap, not assumed glue. |
| Compression | Same semantic bytes, stream/connection layout, codec/framing version, chunking and flush schedule | Off versus one source-qualified algorithm/configuration. Separately vary chunking or flush only in a later labelled comparison. Include compressible structured text and a bounded poor-compression corpus. |

These are alternative experiment arms, not parallel production migration paths. Begin with the simplest eligible pair rather than an unbounded cross-product of settings. A framework/codec adapter must pass the relevant E2 framing/validation/cancellation gate before its speed is meaningful. Tokio remains the runtime; CPU-heavy or blocking work must have an explicit, measured placement rather than being hidden inside a nominally async call.

## Correctness and calibration cases

Each case has an opening identity, exact finite stimulus, independent outcome and correlated closure covering the work being claimed. Queue send, transport ACK, stream finish, returned credit and a generic wrapper are scored at their actual boundaries. Missing observability makes the dependent claim inconclusive. Do not add a production test hook or new event during this research task to fill a gap. A declared sampling instrument would be a separate observation profile; polling until an outcome appears is not a completion oracle.

Load/hold release belongs to an independent fixture controller. It must not wait for a reply or volume checkpoint from the producer deliberately blocked by that hold. Name the reachable admission/phase facts and the joined closure before running. If the candidate exposes no adequate observation, report the missing seam; do not replace it with polling or a sleep-until-quiet verdict. Real-time offered-load pacing is an explicit benchmark input, separate from proof that an operation completed.

| Case | Action and expected observation | Calibration or failure that must be detected |
| --- | --- | --- |
| P0: clock and observer qualification | Confirm each stopwatch's units, monotonic timebase, start/end boundary and correlation. Introduce a separately measured hold at one owned stage after submission and before result. | The scoped stage and enclosing observation must reveal the hold; an unchanged unrelated control helps expose instrument noise or wrong identity. No uncalibrated cross-clock subtraction. |
| P1: process/auth/socket baseline | Compare fresh CLI and eligible reused-socket calls, warm and setup-inclusive observations separately. Validate result identity/content and preserve current deadline semantics. | Wrong target, invalid result, stale cache or deadline refusal is not a fast successful operation. A fixture-only echo is not a real session/Git result. |
| P2: small control under bulk | Offer bounded terminal output and large application results while querying a small known state. Include one stalled bulk consumer, if its E3 recovery/admission profile is qualified. | Detect small-call delay, head-of-line framing, dropped/mis-scoped results and work retained upstream of the nominal bounded queue. Record bulk starvation as well as interactive improvement. |
| P3: input under bulk output | Within eligible new-route arms, send canaries through the actual frontend/socket/Gateway/Host path to a controlled terminal producer with known reply bytes and independent receipt identity. Observe byte echo at the client. | Each measured result must match its actual canary; no automatic replay of uncertain input. A lost input, missing producer response, stale terminal state and missing frame observation are different outcomes. This provides no current-versus-new terminal cost or native latency result. |
| P4: native terminal echo gate | Current client-clock parser/presentation timing is ineligible under the observation decision above. E1 correctness, or a one-shot state read at an independently closed checkpoint, cannot turn it into latency evidence. Any later admitted native observer must use the actual Ghostty/relay path and qualify start identity as well as the stop. | A future observer must detect the suppressed-echo control without reporting successful zero latency, and reject stale/wrong-surface frames. Keep physical native key admission, programmatic input submission and automation-request timestamps distinct. No existing eligible parser/presentation instrument is claimed. |
| P5: compression costs and bounds | Transfer identical bounded payloads off/on; compare decoded bytes/state and queue/resource outcomes, then CPU/latency/byte counts. Record algorithm/level/dictionary, frame size, flush, reset and retained codec state. | Corrupt/truncate a small fixture frame or interrupt a stream at a declared point; the result must refuse or report its actual incomplete outcome rather than silently installing valid-looking partial state. E2 owns semantic/frame validation; E1 owns terminal continuation. |
| P6: connection replacement | Under the declared recovery profile, interrupt one connection while another consumer continues, then replace the connection and restore only the selected subscriptions/attachments. | No invented input delivery result or replay, no stale incarnation application, and no incorrect success from a reconnected socket alone. Keep setup/handshake and first-correct-state times separate from steady state. |
| P7: loaded native application | Use a real-sized fixture or a live-derived stress population with current marker/PID and actual telemetry. Keep the documented strict-sidebar zero-PTY population separate from a terminal-fleet contention workload. | A tiny semantic fixture cannot satisfy this claim. Require the same meaningful state/results and native application scope before interpreting CPU or MainActor improvements. |
| P8: observation overhead | Run the same correct finite workload with a minimal required observer and with the complete measurement profile, in alternating paired order. | If probes materially change contention, report that cost/uncertainty. Reduced observation must not remove the correctness oracle and manufacture a better latency result. |
| P9: codec-state cancellation scope | Declare codec-state identity/scope: independent frame/member, stream, or a context spanning operations. Cancel operation A mid-transfer while B shares the relevant transport/context; continue or replace the connection under the declared contract. | Observe B's correct result or its explicitly declared wider failure, A's actual continued bytes/cost, codec finalization/reset and uncertain effects. If state coupling changes the fixed per-operation cancellation semantics, the arm is not eligible for that same-contract comparison. Do not silently reset shared history, drop unfinished bytes or claim cancellation freed their bandwidth. |

P2/P3 begin with one explicitly identified experiment controller and other consumers that do not mutate its viewport. This isolates transport contention without selecting the product's eventual multi-device controller policy. E3 retains the separate controller-transfer/resize experiment. Reconnection arms remain conditional on the declared retention/recovery promise; no unlimited history or automatic workload restart is added.

## Result accounting

For every offered operation retain its request/canary identity within the private fixture, relevant scope/incarnation and each observable stage. Use a mutually exclusive primary result disposition: locally ended before submission; validated response with correct/wrong/refused meaning; or attempted submission without a validated response, carrying its reason. Record independently observed admission/effects, cancellation and parser/pixel/presentation observations on separate correlated axes. A cancellation can coexist with an uncertain or completed effect; it is not a disjoint proof that nothing happened. Preserve contradictory observations for diagnosis rather than rewriting them into success. Publish only safe aggregates.

Report offered, submitted/attempted, validated-correct, validated-wrong/refused and missing-result counts with their exact definitions, plus separate admission/effect/cancellation/observer outcomes. Pending work remains accounted at run closure. Percentiles over successful samples must state that denominator beside failures and pending work; a missing response has no measured successful latency and cannot be entered as zero or silently dropped.

Report p50/p95/p99/max with retained sample count, rank resolution, repeated-run variation and separate setup/warm populations. A product pass/fail needs selected owner tolerances; exploratory source-qualified measurements can still establish costs and reject incorrect candidates without those tolerances. Do not subtract unrelated percentiles to attribute a stage or use a single observed path RTT as the application RTT.

Record deadline scope, position in that scope, remaining budget at submission and the client's elapsed observation cutoff for every affected sample. A deadline ending an already attempted call censors its validated-result observation; preserve the elapsed lower-bound/no-result evidence and the actual effect uncertainty. A pre-submission expiry is admission/queue failure, not a right-censored service completion. Successful-only quantiles are conditional/descriptive and may bias low when deadlines remove slow observations: they are not a full offered-population tail even with a failure count beside them. Report tail bounds or not-estimable when observations do not identify the quantile; assume no independent censoring model and do not extrapolate a success tail over missing work. If no censoring occurred, report that observed fact rather than assuming it. Per-run populations remain separate unless pooling is justified; do not average their percentiles.

Track separate byte boundaries: semantic/plain payload, encoded application frame, bytes accepted/read by the transport API, protocol-emitted datagrams, observed host/kernel/network traffic where qualified, and independently verified application result. State which headers, encryption, retransmissions, other streams and interfaces each counter includes. A connection-wide counter cannot attribute one operation during competing traffic without an additional valid observation seam.

Track codec/serialization CPU, executor occupancy, native MainActor execution occupancy versus await time, allocations, retained backing buffers, decoded expansion, queue age, blocked tasks and process footprint. A byte-credit window or declared frame cap does not bound all pending snapshots, producers, decoder output or connection state. Inspect admission/allocation contracts before claiming a general resource bound; finite stress only supports its exercised population.

Use the [owning observability proof model](../../../../../architecture/observability/observability_and_traceability.md:172) for native/loaded claims: current identity, marker-scoped Victoria evidence and required telemetry projection checks. State files/JSONL, parser reads and captured pixels are distinct evidence. Actual presentation and observer timebases remain unqualified until calibrated for the precise instrument and surface.

## Decisions the results can support

Reject an exercised arm that corrupts outcomes, lies about continuity/effects, or fails the declared admission/cleanup profile. Mark a claim inconclusive when its observer, identity, causal closure or policy is absent. If equivalent correct arms differ measurably, report the gain and the paid CPU/memory/bandwidth/maintenance cost with uncertainty. A priority arrangement that starves required bulk work or compression that merely moves the bottleneck is not an unqualified improvement.

The experiment can identify eligible stream/connection layouts and per-class compression candidates. It cannot choose owner latency/resource tolerances, change the selected iOS Gateway role or independent Host-local ingress, settle remaining shared-layout/controller details or grant a dependency safety waiver. It also cannot establish full macOS/Linux feature parity from a faster control exchange. No product implementation, prototype, test, benchmark, native capture or remote environment has been run for this procedure.

The bounded Advisor challenge and Lead source dispositions are recorded in [the E5 disposition](../../../../../../tmp/practices-research/2026-10-15-daemon-extraction-survey/e5-challenge-disposition.md). That source review establishes no runtime performance or whole-system design acceptance.
