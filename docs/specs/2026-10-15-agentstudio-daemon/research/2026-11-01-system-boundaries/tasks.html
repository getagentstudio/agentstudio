Follow work and its evidence

The task system and loose messaging both support coordination. Their records answer different questions. Existing provider-control and settlement machinery can be reused where its contracts fit; the full delegated-task model is still to bind.

Support standalone and board-linked delegation. Both retain durable execution identity, outcome and recovery. Standalone work needs no synthetic board task or schedule.

A task decomposition, delegation relationship and OS process tree need explicit associations. Parentage alone does not settle cancellation rights. A delivered result is evidence for the task owner; it does not independently overwrite task acceptance.

Proposed task-to-execution boundary

Admits the authorized execution association, with a board-task link when requested.

Controls the exact provider operation and records its observed settlement.

Retains execution outcome. When linked, evidence reaches the board-task owner. Acceptance authority remains an explicit contract.

This is an ownership proposal, not a selected task schema. Router's existing automation run requires a schedule ID and can finish on peer-message delivery. Its exact-turn settlement mechanisms are useful; the whole row is not automatically a general delegated-task record.

Its provider-operation store is also metadata-only. After live settlement output is lost, the current wait path can report output unavailable. Durable standalone execution needs an explicit work/result/evidence and recovery contract; retaining operation metadata does not select that contract or permission to copy full transcripts.

What must commit together?

Current Studio accepts a queued notice and advances its supplied handled cursor inside the same database write. The cursor can remain private while eligible notice data reaches a copy. Different audiences do not imply different authoritative commits.

Reads an eligible notice and its source position. File reading is outside SQL.

Checks scope and intent; commits accepted content and the required handled position together.

Copies declared committed data and prepares a qualified view. It does not repeat the command.

Current context “changes” also advances reported answer positions, confirms receipts and may prune events. It needs an authoritative write path. A Gateway copy cannot silently substitute for those effects.

A native effect has its own boundary

Annotation output has a preparation commit, an actual clipboard/file effect, and a later finalization commit. If the effect succeeds but finalization fails, the current implementation reports partial success. Replicated rows do not execute that effect again.

Use the right delivery shape

Commands call their owner. Ordered facts retain source order. Replaceable observations can be coalesced only where that meaning is valid. Terminal buffers and finite file/review content use their own bounded paths. A universal bus does not replace those contracts.
