Keep the active turn running

The selected outcome

Active provider turns must keep running through a planned Host upgrade. Independent execution custody must be qualified. This selects the outcome; it does not yet select a process, protocol or handover implementation.

Keeping a task record, restoring a conversation and continuing its original active turn are different promises. The owner selected active-turn continuity for planned Host upgrades. Abrupt crashes, power loss and replacement of the execution owner itself need their own contracts.

What Router currently does

The checked explicit replacement path owns teardown before reexec.

ACP retirement publishes lost/unloaded state and kills/reaps a still-live child. The retained app-server also has a shutdown path.

Starts after the retained-child teardown. This path is not a seamless live-turn handover.

This is source-observed orderly lifecycle behavior at Router 1cf0ce5a6, not a crash experiment. It cannot be inherited unchanged as the Studio upgrade contract. Independent checking confirmed this constraint.

Candidate: execution custody outside Host replacement

Exposes machine capabilities and reconnects after upgrade. Replacing it does not own stopping the active provider turn.

Retains the original provider process, turn/control association and pending interaction custody while the Host interface is replaced.

Proposed mechanism to qualify: keep Router's provider owner outside the Studio Host replacement boundary and reuse its typed semantics through a deliberate interface. Another qualified handover is possible. A separate process alone proves neither lifetime independence nor authority.

The cost is lifecycle, identity, admission, reconnect, version and packaging work. The gain sought is the selected active-turn continuity. Upgrading the execution owner itself must not be smuggled into this claim.

Observed: one native lifetime primitive

The corrected local probe captured the command and turn start, confirmed SIGKILL of only the requesting CLI, then released a private value. The same command returned output matching the marker after trimming with exit code 0 and the same native turn completed. A separate event observer remained as prototype custody.

All three attempts and exact proof limits remain visible. The first attempt was inconclusive for hard loss; the second exposed the fixture's nullable-field mistake. The runtime's digest-verified schema guided the correction; the hang bound and success predicate were not relaxed.

What must be shown

The full Host obligations remain to qualify. The local native caller-loss primitive above was observed with retained prototype custody; no replacement adapter, actual Rust Host replacement, provider-process handover or last-subscriber loss was exercised. Existing ZMX detach behavior remains a separate boundary.

The qualification protocol and readiness check distinguish this bounded result from the actual product Host-upgrade proof and the remaining target/provider/interaction cases.

The current facade accepts turn/interrupt's turn ID but discards it before resolving the active operation. A delayed stop naming turn A can select later turn B. A repair or another qualified control path is needed before this interface can satisfy the exact-attempt cancellation case. This is source evidence, not an executed reproduction.

What remains to choose

The outcome is settled. The actual execution owner, process placement, control/handover contract and resource/target support remain to design and qualify.
