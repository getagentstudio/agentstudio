## Persisted Sessions context versus current runtime status

**Source:** `statusContext(paneId)` opens one read closure and calls `loadContext(.pane)`. Its exact table union is:

- `sessions_operation`: global MAX(`commit_revision`), operation kind/binding and revision ordering.
- `sessions_pane_binding`: generation, pane/conversation/source-generation identity, lifecycle/origin/transition, committed revision, start/end, resume and owner fields.
- `sessions_conversation`: provider identity/conversation reference and timestamps.
- `sessions_source`: source identity/generation, provider version/mode/qualification, status/cursor/start/end/revision.
- `sessions_evidence`: occurrence/binding/source/turn/subject, kind/origin/status effect, occurred/commit/admission ordering and provider signal payload discriminants.
- `sessions_provider_question`, `sessions_provider_question_option`: conditional ordered nested questions/options when `has_questions` is set.

Bindings join operation and conversation rows. Evidence joins binding and operation rows; the operation kind plus sessionStart evidence determines the binding-start-record set. Evidence replay ordering uses admission sequence/time/occurrence identity. The loader also reads source rows even though the final summary exposes less. Malformed stored identities/enums/payloads can fail decoding. Sources: [status read](../../../../../../Sources/AgentStudio/Features/Sessions/State/SQLite/SessionsRepository+StatusReads.swift:19), [loader](../../../../../../Sources/AgentStudio/Features/Sessions/State/SQLite/SessionsRepository+Loading.swift:33), [binding join](../../../../../../Sources/AgentStudio/Features/Sessions/State/SQLite/SessionsRepository+Loading.swift:82), [evidence join](../../../../../../Sources/AgentStudio/Features/Sessions/State/SQLite/SessionsRepository+Loading.swift:148), [nested payload](../../../../../../Sources/AgentStudio/Features/Sessions/State/SQLite/SessionsRepository+ProviderQuestions.swift:30).

**Source:** This SQL decode can be repeated as a read given a coherent declared row set. Current `sessionSummary/readSessionStatus` additionally starts viewed ingress, lazily loads open asks, restores runtime states, consumes viewed/retired batches and publishes. Restore replays applied evidence and retains existing ask/line/viewed overlays; admitted monotonic instants and current confirmed-live state are runtime inputs. Reducer/summary folding can be repeated only with those explicit inputs, not solely persisted evidence. Person focus supplies viewed instants; a later view can change done → ready. ## Open asks, lines, detail and their child tables

**Source:** `openAskSummaries` calls `ensureOpen`, then reads all distinct session senders from `pane_request`. Each summary reads `pane_answer_position.ask_sequence` by pane + writerKey and groups open request counts by exact `sender_binding_generation` and reason. The writerKey excludes binding generation; the count filter does not. `advancing:false` is pure SQL; `advancing:true` UPSERT-increments ask_sequence inside send/settlement. This sequence is separate from `last_reported_position`. Sources: [open-ask SQL](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage+OpenAsks.swift:5), [writer key](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage.swift:122), [summary entry](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService.swift:178).

**Source:** Title/line decode reads `pane_state`; line refs also read `pane_state_action`. Line stale is `stored stale || expires_at <= now`, so a read-time result can differ without a stored stale update. Current ordered writes read retirement/current binding/write-order state, update the accepted counter, upsert title/line, replace line refs and bump `detail_revision` on the pane's agentTitle row. Only monitoring line work is forwarded as Sessions monitoring input; title/line content is not turn truth. Sources: [current values](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage+CurrentValues.swift:6), [ordered writes](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+OrderedWrites.swift:24), [revision](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage.swift:145), [bridge mapping](../../../../../../Sources/AgentStudio/App/PaneContext/PaneContextSessionsBridge.swift:64).

## Current writes hidden behind read-like entry points

- **Opening:** first `ensureOpen` writes .appStopping settlement for persisted open blocking asks, accepts post-commit outcomes/open-ask updates, drains pending retirements, refreshes deadlines and starts presentation. Failure clears the opening task for later demand. Subsequent opening checks still drain retirement work. [Source](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService.swift:93).
- **Changes:** `pane.message.changes` UPSERTs last_reported_position, confirms matching writer receipts through that reported position, bumps revision and prunes old acknowledged non-notice event rows. Answer entries reconstruct current request/answer children. Returning nextPosition does not itself report that next position; the caller supplies it in a later request. [Source](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Changes.swift:11).
- **Person settlement:** answer/dismiss/withdraw loads full message/form state; answer validates form and reads current SQL binding to choose initial receipt. It updates request terminal/answer/receipt/position, inserts typed answer values and applicable event, advances ask sequence and revision, then notifies waiters/status/publication. An answer is not proof its sender consumed it. [Source](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextAskSettlement.swift:11).
- **Notice read state:** explicit markRead changes notice state/settled time/position and revision. Detail rendering alone does not call the changes acknowledgement transaction. UI markRead/answer remain explicit actions. [Service](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Messages.swift:144), [UI, reused](../../../../../../Sources/AgentStudio/App/PaneContext/PaneContextPopoverController.swift:181).
- **Generation end:** sessionEnded stales generation-owned agent lines and changes receipt notYetConfirmed → unconfirmed for that sender generation, bumps affected revisions, clears monitoring sink, publishes and refreshes deadline. This requires an actual lifecycle input, not merely a read of existing rows. [Source](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:153).

## Existing scheduler, start and failure boundaries

**Source:** Production composition constructs the service with the shared application-local datastore, current graph directory, Sessions callbacks, ContinuousClock and Date wall time. Construction connects owners but does not eagerly call ensureOpen. The constructor does start a buffered retirement-wake drain; retirement can wake ensureOpen without an open popover. A read, write or retirement demand can perform first opening. Sources: [boot composition](../../../../../../Sources/AgentStudio/App/Boot/AppDelegate+IPC.swift:299), [owner composition](../../../../../../Sources/AgentStudio/App/PaneContext/SessionsPaneContextComposition.swift:34), [constructor wake](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService.swift:78).

**Source:** refreshDeadline reads MIN over four table families: open blocking ask deadlines; non-retired non-stale line expiry; retirement purge_after; settled visible request/notice visibility expiry. It fences stale deadline reads by generation and schedules the existing RepositoryRetentionScheduler. First opening and subsequent message/line/settlement/retirement/session-end/timed mutations refresh it. The scheduler owns one cancellable sleeper and one admitted callback; firing clears its pending deadline, and successful deadlineReached re-arms through refreshDeadline. Sources: [selection/arming](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:76), [scheduler](../../../../../../Sources/AgentStudio/Core/RuntimeEventSystem/Retention/RepositoryRetentionScheduler.swift:19).

**Source:** deadlineReached runs one write closure: capture presentation revisions; settle due blocking asks; expire lines; hide settled messages; purge due retired panes; collect changed sources. Only after commit does it accept outcomes, publish and refresh the next deadline. Explicit purge targets are pane_state, pane_request, pane_event, pane_write_order, pane_epoch_claim, pane_answer_position and pane_retirement; named child FKs cascade. Sources: [timed commit](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:114), [expiry](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:256), [hiding](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:312), [purge](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:333).

**Source limit:** deadline-read failure is swallowed for later-demand retry. Timed-transaction failure publishes nothing and does not itself refresh/retry; no dedicated backoff loop exists. Another concurrent refresh may already have left pending work. Retirement failure requeues pending panes; purge failure waits for later demand. Shutdown cancels/joins sleeper and admitted validation, then attempts blocking-ask settlement. Once armed, timed maintenance does not need an open popover; never-opened or failed-service progress is not established here. Removing read-side maintenance alone is therefore not evidence of equivalent no-client behavior. Sources: [failure catches](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:109), [retirement retry](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:55), [service stop](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:193), [scheduler shutdown](../../../../../../Sources/AgentStudio/Core/RuntimeEventSystem/Retention/RepositoryRetentionScheduler.swift:59).

## Currentness and unresolved closure

Pure query/fold classifications require coherent parent/child rows, ordering, policy/time and all named runtime inputs. They do not establish a coherent copied cut, ongoing observation, revision incarnation, replay retention or native/person currentness. Present owner/drawer grouping is graph/view aggregation, distinct from session binding/evidence truth. Graph presence does not imply a live native window/controller/terminal surface. Popover generation/location/title reads and publication application are current client state.

Exact untraced pieces: full graph storage/restore closure; all provider qualification/liveness/source-generation branches; complete status reducer audit; arbitrary commit-participant tables; full schema/trigger/cascade inventory; every UI form/action/native runner effect; never-opened/failed-service runtime liveness; concurrency/isolation proof across the composed inputs. Those remain gaps rather than inferred requirements or design selections.
