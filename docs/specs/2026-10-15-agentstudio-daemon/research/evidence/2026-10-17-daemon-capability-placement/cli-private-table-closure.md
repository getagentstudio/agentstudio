## Claim replay is separate from current generation and current epoch

source: `PaneContextService.claimEpoch` uses an application-local write closure. Runtime membership/pending-retirement and SQL retirement are checked; a session writer's generation must match the current SQL binding. The IPC adapter first resolves provider/conversation to a binding and rejects historical writers. These checks happen before storage claim replay. ([Service](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+OrderedWrites.swift:6), [adapter](../../../../../../Sources/AgentStudio/App/IPCComposition/AgentStudioIPCPaneContextAdapter.swift:157), [writer resolution](../../../../../../Sources/AgentStudio/App/IPCComposition/AgentStudioIPCPaneContextAdapter.swift:254).)

source: Storage SELECTs claim_id and checks pane_id/writer_key/stream. Matching replay returns retained epoch without modifying the current order row; conflicting scope refuses. A fresh claim reads `pane_write_order.current_epoch`, increments it, resets last_counter and inserts claim/time in that same closure. The claim has no binding-generation field. A retained epoch can be older than a newer order row; subsequent payload admission checks exact current epoch and increasing counter. Claim replay therefore does not certify payload application or current epoch. ([Storage](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage+CurrentValues.swift:133), [write admission](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage+CurrentValues.swift:172).)

source: Claim allocation does not itself bump display revision/publish title or line. `ensureOpen` can separately settle startup asks/drain retirements; retired purge later deletes claims/order/context rows. This is private replay/order bookkeeping influencing an admitted write, rather than a current display read. ([Wrapper](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+OrderedWrites.swift:6), [opening, reused](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService.swift:93), [purge, reused](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Lifecycle.swift:333).)

## Verifier and scope are separate from bearer and current authorization

source: Repository registration checks 32-byte verifier and supplied eligibility inside the write closure, SELECTs pane+record, requires exact equality for existing row or inserts five columns. Pure repository reads cover pane+record, ordered pane list and verifier lookup; multiple verifier matches throw ambiguity. Revoke marks all pane rows revoked. Current migration has unique pane+record index, not unique verifier, and excludes historical diagnostic/runtime/generation fields. ([Repository](../../../../../../Sources/AgentStudio/App/PaneAgents/IPCContinuityRepository.swift:20), [reads](../../../../../../Sources/AgentStudio/App/PaneAgents/IPCContinuityRepository.swift:57), [ambiguity](../../../../../../Sources/AgentStudio/App/PaneAgents/IPCContinuityRepository.swift:90), [current migration](../../../../../../Sources/AgentStudio/Core/State/MainActor/Persistence/WorkspaceLocalMigrations+IPCCredentials.swift:117).)

source: Resolver hashes separately presented bearer text, requires registered stored match, and returns pane/workspace/record resolution. Registry may instead match a currently memory-issued pane verifier or memory-only debug credential. It checks canonical membership and installs a current-runtime principal/lease with noApprovalAuthority. Current authorization rechecks membership and lease state; method authorization remains separate. The table is continuity state, not raw bearer possession, provider binding authority or native surface availability. ([Resolver](../../../../../../Sources/AgentStudio/App/PaneAgents/IPCContinuityCredentialResolver.swift:14), [authenticate](../../../../../../Sources/AgentStudioAppIPC/AgentStudioIPCAuthentication.swift:265), [scope/principal](../../../../../../Sources/AgentStudioAppIPC/AgentStudioIPCAuthentication.swift:458), [recheck](../../../../../../Sources/AgentStudioAppIPC/AgentStudioIPCAuthentication.swift:395), [method authorization](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCServer.swift:379).)

source: Login changes connection/lease state and may queue a separate credential write before returning. Startup also installs issued-credential sink/queues candidates. Final revoke changes runtime registry/connections before queued durable revoke. FIFO persistence counts/removes failed attempts without an automatic requeue/backoff; drain result is the separate durable completion boundary. Thus pure verifier SELECT is not the full login effect. ([Server startup](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCServer.swift:150), [login](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCServer.swift:330), [final revoke](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCServer.swift:211), [persistence lane](../../../../../../Sources/AgentStudioAppIPC/AgentStudioIPCCredentialPersistence.swift:94).)

## Source positions, accepted notice and store/server dedup differ

source: CLI identity admission SELECTs LIMIT2 and requires exactly one UUIDv7/channel-matching row. Read-only open rejects unknown migrations, permits known older schema subset, and creates/migrates nothing. Writer open can initialize/migrate/set journal configuration after version/channel admission. Store identity is a producer-file incarnation/cursor namespace, not caller authority. ([Identity](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:418), [reader](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:206), [writer](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:96).)

source: `appendNotice` runs in an immediate write transaction and dedups globally by message_id. Existing ID returns the original entry/payload/time without checking new intent fields. Fresh insert records notice envelope and rounded millisecond creation time. Offline fallback accepts only eligible never-submitted notice requests with self/matching pane; delivery-uncertain failures do not qualify. Queued means producer append, not app admission. ([Append](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:234), [eligibility](../../../../../../Sources/AgentStudioIPCClientCore/OfflineOutbox/PaneNotificationOfflineHandler.swift:6), [handler](../../../../../../Sources/AgentStudioIPCClientCore/OfflineOutbox/PaneNotificationOfflineHandler.swift:58).)

source: App drain reads identity → Local cursor → reopened CLI batch and rejects identity mismatch. Readout SELECTs all rows above cursor in id order, with typed entries and decode issues; there is no SQL page limit. Readout does not acknowledge/delete rows. Drain merges entries/issues in order, validates method/notice/pane/message and resolves writer before service admission. Accepted new notice or equal existing server intent commits cursor participant in the same Local write; malformed/refused commits cursor separately; retryable stops prefix. Server intent equality compares semantic fields, unlike store-only message-id dedup. ([Readout](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:282), [drain](../../../../../../Sources/AgentStudio/App/PaneAgents/PaneCLIOutboxDrain.swift:69), [intake checks](../../../../../../Sources/AgentStudio/App/PaneAgents/PaneCLIOutboxDrain.swift:152), [participant](../../../../../../Sources/AgentStudio/App/PaneAgents/CLIOutboxCursorCommitParticipant.swift:11), [service, reused](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Messages.swift:20), [intent comparison, reused](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextStorage+Messages.swift:122).)

source: Therefore handled is a disposition prefix and can include no accepted notice. There is no transaction spanning CLI source read and Local admission. Participant conforms to Sessions and context protocols, but sole production construction found is notice drain; conformance does not prove a hook outbox. App boot starts one detached drain after listener startup. ([Disposition loop](../../../../../../Sources/AgentStudio/App/PaneAgents/PaneCLIOutboxDrain.swift:107), [production construction](../../../../../../Sources/AgentStudio/App/Boot/AppDelegate+IPC.swift:266).)

source: Login optionally returns identity-bound Local handled position, not a fresh operation-specific result receipt; auth.status omits that read. Client completion passes that mark to cleanup. Cleanup opens writer before optional mark guard, so setup can occur even without a usable mark; deletion requires matching identity/positive handled position and rechecks identity inside transaction. It deletes only id<=handled AND older than one-day retention. Unhandled rows have no expiry here, and source IDs use AUTOINCREMENT because Local cursor survives deletion. No display/user consumption follows from this cleanup position. ([Read-through](../../../../../../Sources/AgentStudio/App/PaneAgents/AppCLIStoreReadThroughReader.swift:15), [login/status](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCServer.swift:350), [client completion](../../../../../../Sources/AgentStudioIPCClientCore/AgentStudioIPCClientCore.swift:50), [cleanup](../../../../../../Sources/AgentStudioIPCClientCore/CLIStore/CLIStoreCleanupHandler.swift:26), [purge](../../../../../../Sources/AgentStudioCLIStore/CLIStore.swift:315), [policy](../../../../../../Sources/AgentStudioCLIStore/CLIStorePolicy.swift:9).)

## Producer allocation and answer progress are separate from operation effects

source: `cli_state` has three literal kinds: titleWriteNumber, lineWriteNumber and answerPosition, keyed by kind/pane/sessionRef (provider:conversation or pane in runner). Reserve ensures row and persists/reuses pending claim before network; accepted epoch allocates counter; existing epoch allocates next counter before payload submission. Each step is its own immediate local transaction. Stored epoch/claim/value cannot certify that title/line applied. Server binding generation and order checks remain separate. ([State methods](../../../../../../Sources/AgentStudioCLIStore/CLIStore+State.swift:33), [runner](../../../../../../Sources/AgentStudioIPCClientCore/PaneCLICommandRunner.swift:147), [key](../../../../../../Sources/AgentStudioIPCClientCore/PaneCLICommandRunner.swift:245).)

source: epochSuperseded clears state only for the rejected stored epoch; lastAccepted retains max counter for matching epoch; writerReplaced does not modify state in this runner. Stale is final for current payload, and runner throws instead of replaying that intent under a new epoch. ([Reconcile](../../../../../../Sources/AgentStudioCLIStore/CLIStore+State.swift:75), [runner outcome](../../../../../../Sources/AgentStudioIPCClientCore/PaneCLICommandRunner.swift:203).)

source: `answerPosition()` is a nominal read using write transaction and INSERT-if-absent, then SELECT. CLI answers defaults to zero if store/key/read unavailable, accumulates pages, invokes output sink, then MAX-advances local position. After partial pages and later failure it outputs more:true, advances printed prefix when possible, then rethrows. Requesting later server pages already supplies prior nextPosition; the server changes transaction can confirm those earlier receipts before the accumulated output is emitted. Local stored progress is output-sink progress, not proof downstream used an answer. ([State](../../../../../../Sources/AgentStudioCLIStore/CLIStore+State.swift:98), [paged output](../../../../../../Sources/AgentStudioIPCClientCore/PaneCLICommandRunner.swift:96), [sink helper](../../../../../../Sources/AgentStudioIPCClientCore/PaneCLICommandRunner.swift:301), [server acknowledgement, reused](../../../../../../Sources/AgentStudio/Core/PaneContext/PaneContextService+Changes.swift:11).)
