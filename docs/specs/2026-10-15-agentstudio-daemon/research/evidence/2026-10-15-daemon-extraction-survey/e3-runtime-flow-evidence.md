A common envelope does not make these delivery or completion contracts interchangeable. Current losses and bounds below are observations, not proposed future requirements.

## Coordination planes and shared delivery mechanics

The architecture describes **3 planes: event, command, UI**. Its coordination decision table names **7 boundaries**: `WorkspaceActionCommand`, `PaneRuntimeCommand`, `PaneRuntimeEventBus`, direct `TopologyEffectHandler`, `AppEventBus`, `ApplicationLifecycleMonitor`, and local observable UI state. There are **2 concrete shared bus instances** in this inspected path: `EventBus<RuntimeEnvelope>` and `EventBus<AppEvent>`. Owner-local typed fact recorders used for testing/diagnostics are separate seams, not extra shared product-bus vocabulary.

The bus declares **2 subscriber policies** (`criticalUnbounded`, `lossyNewest(Int)`), **3 replay statuses** (`notConfigured`, `complete`, `possiblyTruncated`), and **4 failure classes** (`lossyDrop`, `criticalDrop`, `criticalPressure`, `replayPossiblyTruncated`). `ActionPolicy.critical` / `.lossy(key:)` is a separate reducer classification; a fact marked critical can still cross an earlier finite queue.

## Material constraints and remaining proof gaps

1. **A routing source is not a sequence-owner incarnation.** Runtime channel increments its pane sequence; WSC separately increments `nextFilesystemProjectionSequenceByPaneId` and emits the same `.pane(paneId)` source. Boot topology and workspace activity also use independent counters under coordinator. The shared bus's internal append-order merge preserves current append order, but `source.description + envelope.seq` cannot be assumed universally unique or monotonic across all producers/restarts. Topic filtering and deliberate non-replay emission add legitimate omissions. No durable incarnation/cursor claim follows.
2. **A critical final subscription does not make an exact fact lossless.** Runtime outbound newest128 is earlier; Git/Forge/activity have their own lossy subscriptions; reducer/governors have different replacement/ordering semantics. Local unbounded streams and critical queues move the resource cost rather than establish a memory bound. Which future facts may be latest-only versus must preserve every transition is an owner/contract question, not selected by current queue code.
3. **Replay evidence has multiple scopes.** Runtime local finite count/estimated-byte/TTL replay and shared finite-per-source replay are different histories. Empty local replay cannot distinguish no history from expired/lost history; shared possiblyTruncated is conservative and not a durable cursor. Unlimited source cardinality remains separate from entries per source. No generic resnapshot completion or durable resume capability is demonstrated.
4. **Admission, dequeue, ordered application and native completion are different receipts.** AppEvent termination handled means gesture admitted. Bus counters count enqueue/dequeue. Native runtime result is a handoff. Topology has explicit ordered effects and a later best-effort persistence flush. None by itself proves exactly-once, durable commit, or cancellation rollback.
5. **Currentness is owner-specific.** Ghostty source/surface checks, pane-context projection generations, repository observation lifetimes, Forge request identities, and session binding/source-instant guards protect different things. There is no universal stale-operation/attachment/controller-generation check supplied by generic envelope metadata. A new client socket, resumed transport, logical session and terminal process do not become the same identity here.
6. **Cancellation is not uniformly joined.** Several actors/coordinators have explicit owned-work shutdown joins; PaneTab notification tasks cancel without join, AppEvent helper has no join, reducer has no explicit join/flush. Runtime finish cancels buffered outbound delivery; its join covers only that worker. An experiment needs an actual correlated closure for the behavior it claims, rather than treating task cancellation or subscriber count as completion.
7. **Declared/live and native/domain separation matter.** Some families have no demonstrated live producer/consumer in the bounded search, and browser/diff/editor publications are not necessarily consumed by the major shared subscribers. Native geometry/focus/local controls already use direct presentation owners. These facts neither justify dropping declared parity requirements nor justify moving native UI truth to a server.
8. **The E3 terminal/failure oracle remains experimental.** This review does not establish PTY size/SIGWINCH, output continuity, VT chunk-log failure behavior, slow-reader heap growth, reader-custody lifetime, controller transfer, disconnect catch-up or active-viewer progress under blocked peers. It provides current source constraints for the Lead's procedure. The same admitted semantic traces, actual post-state/effects and correlated failures still need real experiments before a topology or primitive can earn those guarantees.

The only written artifact is this evidence file. Vocabulary/link consistency is a static check, not test/runtime proof. Lead verification and the Advisor's challenge remain independent acceptance steps.
