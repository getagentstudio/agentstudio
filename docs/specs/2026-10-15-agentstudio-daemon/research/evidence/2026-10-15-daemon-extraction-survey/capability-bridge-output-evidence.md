All calls use [control correlation][control] (paneSessionId, workerInstanceId, requestId, positive requestSequence), surface/worker-derivation/current-install admission and per-operation lifetime; those identities are not annotation/output IDs. Request and result payload types are exhaustively bound by [CallRequest][calls] and [CallResult][results]. The 16 rows retain distinct semantics; detailed exact fences/receipts remain in [E2][e2].

## Annotation operation coverage and retained meaning

All 22 [wire operations][annops] are accounted for by the existing [per-operation 22-row matrix][e2]; grouping here is an index, **not a claim of identical semantics**. [Command shape][anncall] separates File versus Review source admission; domain IDs use [scope-typed UUID wrappers][annids], while wire UUIDs/editToken strings and expected session/thread/message/draft/saved/projection revisions have different roles.
| Exact operations | Current effect, canonical result and retained meaning |
| --- | --- |
| `session.discover`; `demand.acquire`; `demand.release` | Read discovery (adapter discards list); register fresh runtime demand generation/detail; release runtime demand. No common durable mutation/receipt. |
| `root.create`; `reply.create`; `draft.flush`; `draft.edit.acquire`; `draft.edit.release`; `draft.save`; `draft.revert` | Source/session/edit ownership and expected revisions vary by operation; all 7 return canonical current message or exact removal tombstone. Saved body/revision, unsaved draft and live writer token are distinct; stale-token/revision repetition is not generic idempotence. |
| `thread.resolution.set`; `session.lifecycle.set`; `continuity.choose`; `source.refresh` | Resolution/lifecycle/fingerprint/relationship changes with operation-specific fences. `source.refresh` can commit relationship/fingerprint then return stale; expected epoch/current demand differs from persisted semantic revision. |
| `output.scope.commit`; `output.preference.changeFolder`; `output.reveal` | Durable exact-byte attempt preparation plus native effect/finalization; application-lifetime in-memory folder choice; existing succeeded JSON-file Finder reveal respectively. No shared output success boundary. |
| `output.handled.clear`; `output.history`; `output.repeat` | Clear matching human handled membership; bounded newest-first summaries excluding cancelled; explicitly repeat **unknown** attempt into new ID with exact old bytes/membership/destination and lineage. History is not a complete effect journal or generic retry ledger. |
| `message.viewed.mark`; `recovery.acknowledge` | Per-item changed/alreadyViewed/notFound/notAgent/stale results with saved-revision checks; durable recovery-provenance acknowledgement respectively. Mixed viewed dispositions can occur in one transaction. |

## Eight decisive responsibility units and concrete proof gaps

| Unit | Current source/effect/location (D) | Counterexample/transitive limit; proof modality |
| --- | --- | --- |
| B1 — Control admission and receipts | [Provider][provider] can execute annotation SQL/native handlers or install admission **before** [generic completion][dispatcher]; other calls apply effects afterward through [committed dispatch][committed]. Generic succeeded can wrap typed failed/partial/rejected; [operation table][optable] is session-local, can retain late unknown evidence, and forgets results/watches at session end. | D: response construction is neither uniformly no-op nor uniformly durable completion. Existing table/dispatcher tests cannot establish restart-persistent or cross-service receipts; decisive proof is operation-specific real owner post-state plus loss-point receipt behavior. E2's corrected completion-test claim remains: missing-admission refusal did not prove deferred annotation SQL. |
| B2 — Finite source reads | [File source][filesource] opens a validated regular file, checks opened descriptor identity/containment, streams and checks final digest; [Review source][reviewcontent] acquires/settles a publication-content lease and validates descriptor/range integrity. Bytes are read on the machine owning the currently resolved source. | D/T: [complete-file/symlink tests][filetests] compare independent source bytes and a containment race; [lease tests][reviewtests] exercise cancellation, A-after-B-commit and A-after-B-application. These are component tests, not service delivery or UI rendering; a descriptor/hash does not confer path authority on another machine. |
| B3 — Worker and display publication | [Receipt acknowledger][ack] returns credit at receipt; [post-render owner][render] separately requires matching exact item/context and reconciliation. Install admission, worker/publication applied state, finite-content end and metadata bank installation have distinct identity/currentness. | D: ACK can precede rendering; marker `publication.applied` omits its advanced/duplicate/rejected disposition. E3's sealed-bank proof is coherent publication, not pixels. Proof modality: current worker/publication/item application and DOM fulfillment separately, then native visual evidence only for a visual claim; no presentation timestamp inferred. |
| B4 — Annotation mutation/demand/recovery | [Service][service] awaits committed repository mutation, then invalidates/publishes process-local projection revision; unacknowledged recovery blocks most mutations. [Source refresh][refresh] uses read availability and demand/source fences, may commit before a stale return. Current native installation/worker ownership is checked around awaited work, not universally inside every SQL transaction. | D: failed/conflict is not universal no-effect; demand release is not deletion of saved annotation state. Seven [canonical receipts][receipttests] avoid projection rereads, but do not establish atomic remote revocation. Proof modality: real SQLite post-state/revisions/edit fencing and held-boundary stale/revocation cases; separately prove refreshed projection/application. |
| B5 — Prepared output, attempts and history | [Coordinator][outcoord] persists exact selected saved revisions/bytes before invoking effect; known success then finalizes event/handled membership; finalization failure yields partialSuccess. Recovery marks prepared unknown without replay; repeat permits only unknown and creates new attempt. [History SQL][history] excludes cancelled, limits rows, and joins current membership; [domain state][outdomain] distinguishes prepared/succeeded/cancelled/unknown/finalization_failed. | D: pre-preparation chooser cancellation has no attempt, but [`performEffect.cancelled`][cancelbranch] discards cleanup result and returns destinationCancelled **after preparation** too. Cleanup-only proof is in memory; failure can retain prepared state. T: [repository tests][outtests] prove locking without handled/event on finalization failure; no external effect. Proof modality: exact SQLite bytes/membership/state plus independent native effect and crash/loss observation; unknown is not permission for automatic replay. |
| B6 — Clipboard/file effect and residual failure | [Native effect][native] runs clipboard admission + clear/setData synchronously on MainActor. JSON write admission is fenced, then App-owned detached write is awaited despite later task/install close. Suggested filename path uses O_EXCL and bounded suffix collisions; no suggested filename uses atomic Data.write to the recorded exact destination. Actual effect is on this Mac's pasteboard/filesystem, not abstract repo ownership. | D/T: rejected setData happens **after clipboard clear**, verified by [failure body][nativetests]; effectFailed need not mean unchanged clipboard. I from source: failed [write/close][jsonwriter] attempts unlink but ignores unlink failure, so native file residue is possible and not disproved by cancelled attempt/history omission. [JSON body][jsontest] proves exclusive suffix/non-overwrite in its real-filesystem component case; no fsync/crash-durability proof established. |
| B7 — Folder selection, Finder and cancellation | [Picker owner][picker] latches task/install close, settles once, rejects late callbacks and only accepts a current selected folder; preference is in-memory application lifetime. [Reveal][reveal] checks local path exists then requests Finder selection under admission and returns true. | D/T: selection does not write output; Finder request is not proof of selected pixels or same file incarnation. [Installation tests][installtests] prove pre-admission refusal and post-admission JSON continuation with injected panels/writers; they do not launch Finder or prove OS effects. Proof modality: existing installation fences + owned native chooser/file/reveal result, with machine/path identity explicit. No native Mac effect parity is inferred for Linux Host. |
| B8 — Editor/browser effects outside the16 calls | [Bridge navigation][navigation] allows bundled/about, routes http/https to local default browser via NSWorkspace and cancels in-pane navigation; other schemes blocked. Shared [pane composition][paneexternal]/[toolbar][toolbar] opens a selected local editor target/path through [ExternalWorkspaceOpener][editor]: immediate true schedules async opener; application result/CLI launch are later boundaries. No extra Bridge semantic editor verb exists in the16-case union. | D/T: browser-open return is ignored; editor immediate true is not file loaded/rendered, CLI launch is not its completion. [Editor tests][editortests] inject request runners; [navigation tests][navigationtests] assert scheme sets, not real WebKit/browser launch. Proof modality: independent native target/path/open outcome for the chosen machine. Cross-machine remote path translation/materialization and browser/editor availability remain unproved, not silently supplied by a Host result. |

All named families are covered at their current boundary. Inference remains limited to B6's possible residue; no new policy, schema, storage, owner, transport or normative capability selection is authored. The 8 units preserve local typed contracts without claiming all current Swift machinery must survive. No new UI/screens/atoms/events/stores are proposed.
Source routes: current docs/matrices → targeted dispatch/source/effect/native owners → relevant test bodies. Searches used exact call/operation unions, `NSWorkspace|openExternal|openInEditor|revealInFinder|openFileIn|openURL` in Bridge/App owners and `ExternalWorkspaceOpener` in Sources. Initial nonexistent guessed filenames/globs were corrected with `rg --files`; no missing-capability conclusion used those failures. No OSS/current-web or runtime class was needed. Absolute source links below are primary anchors; prior E2 supplies inherited per-operation detail, not freshly executed proof.
Stop/return: `specification-gap` — Lead owns normative per-capability allocation, result/effect/currentness/location contracts and independent acceptance. Static operation/content coverage and local links are checked; no runtime or formal-review acceptance is claimed.
