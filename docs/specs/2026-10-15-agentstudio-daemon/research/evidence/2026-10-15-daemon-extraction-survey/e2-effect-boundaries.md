# E2: what each receipt actually establishes

The current catalogs do not share one completion boundary. E2 must observe each operation's real effect independently of its RPC response. A successful transport, an admitted operation, a committed database change, a native effect and a displayed result are different observations.

This is source-grounded experiment preparation at AgentStudio `624300332f5e50f7bb8cbb9fc786d5e5b4a3d462` and its exact agentstudio-git pin `4cca397dfc869857064da4e9ec8289ea46adc479`. Tests were read, not run. No Host/Gateway implementation or experiment result is established.

## Small set of discriminating future cases

These are proposed cases, not executed proof or new retry policy. Use isolated fixtures, correlated owner barriers and the mandatory client → socket → Gateway → Host route. Keep a transport-loss outcome distinct from an explicit owner refusal.

| Case | Independent effect observation | Failure/loss point and discriminating result |
| --- | --- | --- |
| Resource creation | Exact fixture graph/core rows and created resource identity; native readiness separately | Lose reply after creation. A second fresh invocation may create another resource; counting replies cannot decide the first effect. |
| Existing retained-message duplicate contract | Stored source-pane/message identity, exact payload and revision | Lose reply after commit; retry the same admitted intent and a conflicting payload separately. Existing duplicate semantics must survive the route. |
| Hook admission versus reduction | Hook evidence identity, reducer disposition, binding revision and activity outcome | Reuse a correlation and inject an ignored valid reduction. Observe the contract rather than assuming one response equals one state change. |
| Terminal input uncertainty | Controlled producer's independently correlated observable state | Lose reply after input handoff; distinguish uncertainty from proven non-delivery. No arbitrary keyboard replay. |
| Source refresh currentness | Canonical relationship/fingerprint and revision, captured with the request's demand/source fences | Compare demand change during the write against failure before the write and same-epoch retry. Both can return stale; the pre-await fence consumes the epoch, while a completed write can also publish invalidation before the stale result. |
| Annotation output custody | Durable attempt/history and exact output bytes plus actual clipboard/file fixture state | Lose session result after admitted native write, then fail finalization. Known effect, partial success, unknown and cleanup-only retry must remain distinguishable. |
| Git promotion/cleanup | Locked expected refs, exact post-state and staging namespace identity | Fail during promotion or after one cleanup page. Detect partial/unknown changes without claiming zero effects from the error. |
| Authority crossing | Target scope/current authority revision at the actual effect boundary; effect counter independent of wrapper settlement | Revoke or change context before admission, during awaited work and after admitted effect. Report each operation's real fence; a shared outer check does not establish universal atomic revocation with SQL. |
| Post-effect error response | Exact retained message row/payload/revision independent of caller error | Inject result-validation failure after commit. A `remoteFailure`, including an invalid-params-shaped error, must not be interpreted as pre-effect rejection. |
| Generic mutation-flag mismatch | Runtime install-admission state for a flagged read; no mutation for a nested annotation read | Expire/revoke after provider dispatch. A non-mutation-flagged authority change can settle failed, while a flagged nested read can settle unknown without changing storage. Check actual effect rather than the flag/outcome alone. |
| Output recovery overlap, conditional on restart scope | Predecessor effect-task custody/extinction and exclusive recovery ownership, plus attempt and file state | Prevent a new recovery owner from marking a still-active predecessor's prepared write unknown. Database writer serialization alone is insufficient if it does not exclude the external effect and recovery overlap. This is a candidate extraction/restart case, not a demonstrated current multi-process bug. |

Calibrate the fixture counter with a deliberately duplicated observable effect and a deliberately wrong post-state. Matching current state alone cannot attribute an effect to one request amid concurrent writers. Reconciliation is strongest when the owner retains an identity, revision, exact bytes or expected-value evidence that correlates it.

## Proof limits and owner gates

The annotation test named “mutate only after committed completion” calls the provider without product admission for its before-check. The provider refuses before invoking that test handler; its title does not establish that production SQL waits for generic session completion. [Test body](../../../../../../Tests/AgentStudioTests/Features/Bridge/BridgeProductSchemeControlCompletionEffectsTests.swift:57), [production provider](../../../../../../Sources/AgentStudio/Features/Bridge/Transport/BridgePaneProductSchemeProvider.swift:294).

No universal atomic product-revocation-plus-annotation-SQL boundary was established. Generic session checks, edit ownership/revision checks, source fencing and native output admission have different scopes. This is a source-proof limit to test at the effect boundary, not an inferred exploit or a chosen replacement mechanism.

The current [Advisor challenge](../../../../../../tmp/practices-research/2026-10-15-daemon-extraction-survey/advisor-e2-challenge.md) accepted the five central findings and added the discriminators above. Lead checked its primary anchors. The suggested blanket internal-error code was unproved and is not adopted: registration-error defaults and schema validation map to invalid params (`-32602`), while other error kinds can map differently. [Error mapping](../../../../../../Sources/AgentStudioAppIPC/AgentStudioAppIPCRequestError.swift:82). No claim that a production encoding fault was executed follows from this source path. For output recovery, exclusive ownership must cover admitted external work and recovery, not merely serialize SQLite transactions. Current cleanup namespace readback establishes present refs, not unique historical effect attribution.

Phone Gateway placement remains the existing owner question. Disconnected authorized agent ingress versus Gateway-only frontend routing is a separate unsettled outcome. Restart persistence, receipt retention, controller/layout policy and performance/resource tolerances are also not selected here. None of these is resolved by a convenient fixture, current implementation behavior or Advisor agreement.
