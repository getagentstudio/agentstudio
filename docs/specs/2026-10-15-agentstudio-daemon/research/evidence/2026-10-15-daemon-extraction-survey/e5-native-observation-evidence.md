| N2 — Text, IME and clipboard direction | [`sendText`](../../../../../../Sources/AgentStudio/Features/Terminal/Ghostty/GhosttySurfaceView+Input.swift:516) calls `ghostty_surface_text` with UTF-8 length; pinned [export](../../../../../../vendor/ghostty/src/apprt/embedded.zig:2067) and [`textCallback`](../../../../../../vendor/ghostty/src/Surface.zig:3382) treat it as paste, including bracketed-paste/newline semantics. Clipboard request `state` correlates that clipboard operation, not a rendered echo. A completed paste request or changed pasteboard does not prove child consumption, output parsing or display. [`queueIo`](../../../../../../vendor/ghostty/src/Surface.zig:862) can discard writes in read-only mode. [Mailbox dispatch](../../../../../../vendor/ghostty/src/termio/Thread.zig:350) reaches [backend queueWrite](../../../../../../vendor/ghostty/src/termio/Exec.zig:403), which copies/chunks into cached buffers and queues the stream write; exited processes accept no more writes. | This establishes the present Ghostty → local attach-process/PTY → ZMX configuration, not measured ZMX forwarding costs or a future Rust route. The write callback [`ttyWrite`](../../../../../../vendor/ghostty/src/termio/Exec.zig:471) destroys the request and handles write errors; it does not announce child echo. No exact hop count, queue-age value or one-key correlation across ZMX/Gateway/Host was established. |
| N4 — Output parsing and text-state observation | Pinned [Exec parse stage](../../../../../../vendor/ghostty/src/termio/Exec.zig:1473) consumes ordered gather-ring batches and owns each buffer until it advances the tail. [`processOutput`](../../../../../../vendor/ghostty/src/termio/Termio.zig:675) locks renderer/terminal state and schedules render **before** advancing the parser with `nextSlice` under that lock. Inspector mode instead records/advances byte by byte and is explicitly slower. [`read_text`](../../../../../../vendor/ghostty/src/apprt/embedded.zig:1884) takes the same state mutex and [dumps selected terminal text](../../../../../../vendor/ghostty/src/apprt/embedded.zig:1904) into allocated output; [`read_selection`](../../../../../../vendor/ghostty/src/apprt/embedded.zig:1867) uses current user selection. [`ghostty_text_s`](../../../../../../vendor/ghostty/include/ghostty.h:449) contains text/offsets and viewport pixel coordinates. | A successful text read can establish parser-owned text at the read, not pixels or presentation. The `tl_px` fields are geometry, not an image. Sampling brackets state observation rather than giving the exact transition timestamp; expensive locking/dump/allocation can perturb the lane. Render scheduling is not a parser-completion receipt, because it is requested first. The local `Timestamp.now(.awake)` here paces cursor blink resets; it is not a per-key/output timestamp. Enabling inspector changes the ingestion path, so an inspector timing cannot silently stand for the normal path. |
| N5 — Terminal query → reply is parser roundtrip | In the output parser, [device attributes/status handlers](../../../../../../vendor/ghostty/src/termio/stream_handler.zig:795) produce DA/status replies; cursor-position response reads the current terminal cursor/origin and formats `ESC[row;colR`. Receipt of the matching query reply can bound parser progress plus return-path costs, subject to actual producer ordering and terminal state. It establishes neither glyph presence nor presentation. These DA/DSR replies contain protocol/status/cursor data, not an arbitrary per-key marker or display timestamp; causal association of one echo with one query remains to be established by the eventual procedure. |

In the async path `frameCompleted` can follow enqueueing before contents assignment; even a healthy frame can be discarded by the size check. The comment “block until ... presented” does not supply a physical-display timestamp: the shown sync code waits for GPU completion and assigns contents. `renderer_health` is neither every-frame completion nor per-key association. No exported terminal-pixel read or presentation receipt was found in the bounded C ABI/renderer inspection below. |

## Source implications, not a selected seam

- An input call's return, a successful PTY write, parser-owned text, query reply, GPU command completion, CALayer contents assignment and displayed pixels cannot substitute for one another. Current source supplies several local boundaries but no verified end-to-end marker across them.
- Source-only tests establish focused logic, not timing fidelity, pixel correctness, actual MainActor/queue costs, loaded latency, allocation counts or display refresh behavior. Inspector mode, text dump locking and fresh CLI process measurement have distinct observation costs/populations.
- [U1/U11/U12/U16/U17](../../../user-requirements.md:24) require frontend → socket → Gateway → Host, Host parity macOS/Linux and a Mac Gateway service; phone Gateway placement remains open. Native Mac renderer code and its iOS comments do not settle phone deployment, native client realization or Rust dependency/unsafe scope. No direct-Host measurement alternative is inferred.
- [U15 and E3](e3-swift-publication-evidence.md:140) require continued Host facts without an attached Swift view; this attached native observation trace proves no renderer-independent Host fact source, persisted history or absent-client latency outcome. It selects no extra parser/VT/store to fill that gap.
- Missing for a presentation claim: a correlated input/echo identity and wrong/missing/stale-echo distinction; observation of the first correct visual frame; validated timing/capture association and timebase; known-delay and output-disabled calibration; actual full-route/current-build/load evidence. Numerical tolerances and the eventual procedure remain with the Lead/owner.
