Filesystem paths are local to the machine running the current app or CLI; current path values carry no cross-machine placement contract. Git-network access is a separate effect from local materialization. The inspected paths do not implement the future Gateway/Host service route.

## Concrete counterexamples and choices still missing

These are source-backed paths, not executed demonstrations:

- **Returned created value is not full content/readiness:** a `WorktreeCreatedSummary` with two missing large files still takes formatter exit 0 and adds “2 large files left as pointers”; native plain creation discards the SDK creation report. Neither form proves all requested file bytes were materialized or a new native terminal/sidebar row rendered. [Created notes][created-output], [formatter][formatter], [native create][native].
- **List/preview is not universally pure:** list, remove dry-run and prune preview call the shared fetch owner before reading/planning. With a resolved origin target and default fetch policy, that owner calls remote fetch. A later read failure can still report the fetch. [Runner:78][runner], [remove:168][remove], [prune:55][prune], [fetch:56][fetch].
- **Remove/apply is not universally complete:** removing directory/admin while retaining a non-integrated branch can be a policy-completed `.removed` entry. Prune apply can skip a dirty/not-integrated entry and still return `applied:true`, exit 0 when no entry is failed. Archive/lock cleanup/branch uncertainty can also yield a failed entry after earlier effects. [Branch retention][remove-preflight], [branch completion][branch-mutation], [prune entries][prune-entries], [prune exit][prune-report].
- **Refusal/error is not universally zero prior effects:** CLI creation preserves earlier fetch evidence on later refusal; removal can leave an archive or completed directory/admin removal before a later stop/failure; result encoding itself follows the operation. [Creation:43–51][creation], [remove mutation][remove-mutation], [CLI:60–78][cli].

The evidence leaves existing G1/G7/G8/G9 choices open: which native/CLI operations become selected service capabilities and where/when they remain available; which source/start/upstream/materialization/ignored-config policy is preserved per invocation; whether app discoverability/publication is part of a result; what active panes/sessions imply for removal; which dirty/evidence/branch/lock choices callers can request; what a completed/partial/unknown/cancelled result promises; and how local paths/native presentation are interpreted across machines.
