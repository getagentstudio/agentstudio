## Identity distinctions used in the table

- **Pane/workspace membership:** current canonical graph presence in one workspace; a pane without a tab can remain present. Layout visibility is not the membership predicate.
- **Bearer/credential identity:** possession resolves to pane/workspace plus opaque credential-record ID; it is not provider executable/process attestation. Repeated login creates different ephemeral principal IDs over the same credential identity. Disconnect releases one principal lease, not the provider conversation or terminal process.
- **Context writer:** pane + sender kind/provider/session reference/binding generation, plus per-stream claimed epoch/counter. This is neither a socket request ID nor generic operation deduplication.
- **Provider session/binding:** provider identifier + caller-reported conversation ID maps to a retained internal conversation/binding/source. A named resume can retain the same binding/source generation; that generation is not necessarily a fresh process incarnation.
- **Terminal/process identity:** opaque `ZmxSessionID` is independent of PaneId and provider conversation. Cleanup additionally observes boot ID, daemon/terminal-leader PID plus start time, process group and session-created-at evidence. A session name or PID alone is not that evidence.

## Search coverage and exact limits

- Traced eight paths only: issuance/auth/lease; Codex/Claude hook ingress; session method/provenance adapter; FIFO/repository/binding/evidence; status/publication/command-exit; ordered context title/line/ask/notice; close/Undo/final revoke/persistence drain; terminal/process incarnation. Tests above were read for assertions and owner closure, never accepted from their names.
- Bounded queries: `SessionsHookAdmission|submitHook` across app source found the direct IPC adapter as the inspected production hook constructor/submission; provider-hook runners in ClientCore call ordinary authenticated IPC. `sessionEvent|session.event|hook|provider` over CLIStore found no session-hook spool path. This is a scoped null, not proof about arbitrary scripts, future adapters or every CLIStore message/effect family.
- The ordinary Sessions transaction has no generic repeated auth/membership fence; other operation owners do. No test was run for revoke/close after queue admission, caller cancellation after committed evidence, post-commit result loss, cross-owner sessionEnded storage failure, simultaneous process/recovery overlap, actual no-Swift/Host restart, remote agent ingress, receipt retention duration or multiple-device controller policy. These remain explicit proof/meaning gaps, not invented failure outcomes.
- Hook process exit0, wire admitted, repository commit, status desired publication, sink application, credential drain and process extinction are separate observations. Correlation/occurrence, durable revision, message ID, epoch/counter, lease identity and process fingerprint must not be conflated into one exactly-once/restart promise.

No generic recommendation or target owner was selected. Lead owns E2 procedure, source verification and owner meaning; this matrix supplies bounded evidence and counterexamples only.
