# I4 — Git mutations, worktree lifecycle and full Linux fork

The usable outcome is selected remote machine-scoped Git/worktree commands through the app and CLI, with a complete macOS/Linux fork counterpart. Basis: U2/U4/U5/U6/U9/U11; K1/K2/K4/K14, R2/R4/R12. The forty-four SDK operations are surveyed vocabulary, not automatically forty-four RPC methods.

Included contract groups to settle: ordinary create modes; lock/unlock; stale administration versus directory removal; conditional branch deletion; remote configuration/fetch/push/probe as selected; staged fetch/promotion/cleanup; full worktree fork; native/CLI create/remove/archive/prune policy.

Fork covers source/destination validation and containment, registration/HEAD/index/ref adoption, eligible file/metadata/name/special-node handling, cancellation and exact residual cleanup. `FICLONE`-level byte success is not the complete capability. Supported filesystems/kernel/profile, clone-versus-copy policy and non-UTF-8/collision/metadata outcomes remain G7; no silent byte-copy fallback is selected.

Current worktree CLI runs local policy before IPC, and native worktree policy differs from lower-level SDK mechanics. Target CLI/app calls the addressed Host's single selected operation implementation. Keep policy differences explicit; preview can fetch and mutate before the displayed decision. Packaging/import must respect the owning Git library rather than add app-local shell invocations as a second implementation.

Every mutation has its own expected-reference, authority, cancellation/join, post-state and duplicate/reconciliation contract. Deleted refs may leave config/reflog; created directories can precede later errors; failed cleanup is residue; uncertain promotion/removal cannot be reported as untouched. Lease refusal does not undo a filesystem/remote-server effect.

Prove real refs/admin/index/directories/content/metadata and supported external remote effects on both platforms, forced races/cancellation, denied or changed targets, and exact typed partial/unknown results. E4's leaf fixture is a prerequisite, not Linux integration parity. IP3 selects worktree machine CLI → attached local Host daemon with start/activation when absent. Exact activation/readiness/failure, discovery and non-session authority remain contract work; UX/frontend CLI retains Gateway access.
