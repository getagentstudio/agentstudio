# I6 — Selected database replication, refill and shared-state experience

The usable outcome is the chosen Host state copied and materialized for clients with honest validity and the selected cross-device tabs/layout/read-mark outcome under IP11/IP12. Basis: U4/U9/U13/U15/U16/U18/U20/U21/U22; K11/K14/K13, R14–R17/C6. The supplied fleet-sync design is evaluated reuse, not proof of an adopted AgentStudio engine.

Decide units and tables before declaring a file replicated. Preserve binding/context/intake and annotation finalization transactions. Separate source truth, private authority/producer state, copy bookkeeping, derived search/prepared views and native memory. All86 current table declarations and597 columns remain evidence, not an export list or an instruction for86 migrations.

The shared plan separates protocol, logical session, transport, writer/capture/retention, lease, receiver and service hosting. Reuse its types/rules through their actual APIs when adopted rather than fork a lease algorithm. Connection replacement does not end the logical session, and that protocol session is distinct from terminal execution. The exact AgentStudio wire/data/application adapter remains to design.

The [current shared-library intake](../../designs/02-data-ownership-replication/research/fleet-sync-consumer-fit.md) identifies the six unmerged implementation PRs and their immutable canonical UUIDv7 replicated-key contract. It narrows the candidate engine profile without selecting a target table list or migration. Ordinary Gateway followers must not become synchronous prerequisites for Host commits; delivery retention/refill and any separate authoritative-copy role need explicit profiles. Durable peer delivery remains optional and distinct from SQL replication and terminal bytes.

Central owns database lease authority, Gateway assumes ready machines, server build is later and database-writer transfer is excluded. Define one authority/database/copy binding, initial setup, renewal/expiry/outage and same-owner restore/refill. Do not introduce Gateway issuance, automatic promotion, indefinite grace or silent loss of authorized Host-local work. If an earlier increment needs this persistence contract, resolve and integrate it there rather than wait for the broad I6 experience.

Receiver apply must declare epoch/position/schema/transaction boundaries and hook-owned state separately from source rows. The proposed ack of committed apply plus durable work intent differs from completed after-commit delivery. Retention for sending differs from retained asks/evidence/history. Private omissions cannot make a read copy silently writer-recoverable; writer transfer remains out of scope.

Sharing across participating devices is selected; exact portable elements, reader/subject scope and concurrent/offline outcomes remain G4/G8/G9/G12. The [proposed realization](../../designs/10-swift-client/shared-client-state-design.md) designates an existing Host for shared workspace composition and keeps markers with their subject Host. This is proposed How, not a new owner decision or a completed migration. Gateways can derive combined reads, but must retain Host/source coverage; agreement is per authoritative resource, not one cross-Host snapshot. Complete/current cannot be asserted for incomplete, superseded or unestablished coverage. Database copies carry data permission, not Host mutation authority or native-effect consent.

Prove real capture→session→two independent receivers→query/client, schema/key/value and transaction closure, bounded backlog/refill/snapshot cuts, lost acknowledgements, source restore/incarnation, crash between apply and after-commit work, source permission and IP4 invalid-writer behavior using controlled clocks. Runtime proof of the actual shared integration is required; codec roundtrips and SQL declaration counts are insufficient.
