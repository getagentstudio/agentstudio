# I7 — Supported clients, concurrent use and operational profiles

The usable outcome is the supported product/client profiles and actual install/upgrade/start/stop behavior around the integrated backend. Basis: all exposed capabilities, especially U1/U3/U6–U13/U16–U21; K2/K6/K12/K13/K14/K15. This is not permission to defer foundational safety, targeting, schemas or concurrency modeling until the last increment.

| Surface | Integration outcome | Real proof boundary |
| --- | --- | --- |
| Mac Swift app | Existing native hosting, command catalog and observation adapters use the selected contracts | Actual app loads the intended helper/backend versions and displays/interacts correctly |
| CLI | Help/arguments/formatting are thin; machine work targets attached Host | Actual worktree CLI → attached local Host effects and absent-local-Host activation under IP3; eligible Host-local session input; separately classified UX/frontend CLI → Gateway effects. Qualify startup/readiness/failure and authority; Mac CLI remote use is required; direct connection versus local Host relay and its credential remain open |
| MCP | Intentional supported tool subset invokes shared operations | Real tool negotiation/caller scope/results, not blanket publication of internal privileged methods |
| iOS UX and Gateway | Embedded Rust Gateway on the phone between UX and addressed Hosts; no required Mac relay | Actual native-binding safety, browser route, startup/suspension/reconnect/device profile under S32; role selection does not prove an always-running mobile process |
| Multiple Gateways and Hosts | Both independent multiplicities with declared shared controller/view/arrangement policy | Real services/devices, equal local IDs/paths, one Host/link loss and isolated progress |
| Install/config/upgrade | Explicit Mac/Linux Host, macOS and iOS Gateway/runtime, app/CLI/provider/backend artifact and channel/version pairing | Actual signed/packaged/deployed identity where claimed, unsupported-pair refusal and partial installation outcomes |
| Observability/shutdown | Owned task/stream/child lifecycle and scrubbed fail-open producer telemetry | Exact shutdown/drain, bounded resources, collector absence/privacy and actual output boundary |

The existing app command identity/display catalog remains one source; interactive presentation is not remote authority. Native lifecycle/clipboard/editor/browser/Finder/chooser effects retain explicit destinations and policies. Host parity does not require Linux Finder or Mac clipboard behavior on the wrong machine.

Operational design must name configuration/credential custody, supported protected-path/TCC profile, service registration/launch, live backend upgrade policy, schema/client pairing, interruption/recovery and privacy. Evaluating a newer ZMX pin is not permission to replace live sessions. A grant to the existing app is not proof that a new Host process has the same access.

Prove actual supported clients/artifacts and all exposed capability contracts together. E5 supplies matched workloads and stage/resource attribution; owner tolerances supply acceptance bounds. Report lower-layer passes and unobserved native/platform/deployment proof separately. Whole-project acceptance requires all accepted requirements, not merely a successful terminal or a clean build.
